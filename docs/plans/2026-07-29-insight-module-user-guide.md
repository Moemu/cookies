## 一、先说整件事：这个模块解决什么问题

一句话：**过去哪些素材在什么条件下有效或失效，下一次应该怎么创作和投放。**

拆成人话，它防的是这三件事：

| 常见毛病 | 这个模块怎么防 |
| --- | --- |
| 「上次那个视频效果好，照着再做一个」——但没人说得清好在哪 | 把创意内容拆成**可比较的变量**（开场方式、产品出现位置、CTA 形式……），才能说"好在开场"而不是"好" |
| 「A 素材点击率比 B 高 30%」——但 A 投的是小红书、B 投的是公众号 | 不同渠道的数字**默认不许放在一起比**，要比得先看到口径差异 |
| 「我们总结过一条经验」——但它写在某个人的周报里，下次没人想得起来 | 经验是有生命周期的对象：待确认 → 已确认 → 待复审 → 已失效，下游只能引用"已确认且未失效"的 |

**它明确不做的事**：不做网盘、不做全局素材排行榜、不承诺"历史好就下次也好"。

### 数据是怎么流动的

这 11 个入口不是 11 个独立功能，是**一条链上的 11 个位置**。按链条顺序读比按导航顺序读容易理解得多：

```
① 数据接入 ─→ ② 分析素材库 ─→ ③ 内容分析
   把平台的        给每条素材        把内容拆成
   投放数字          一个稳定          可比较的变量
   接进来            的身份           （AI 提 + 人工核）
                       │                    │
                       └────────┬───────────┘
                                ↓
                          ④ 投后分析
                     用数字 + 变量解释「为什么」
                                ↓
                          ⑤ 报告中心
                       把解释写成一份复盘
                                ↓
                          ⑥ 经验库
                    复盘里站得住的结论 → 沉淀成经验
                                ↓
                          ⑦ 投前洞察
                 下次做素材之前，把已确认的经验摆上桌
                                ↓
                        （回到创意/策略模块）

旁边还有四个不在链上、但管着这条链的：
  ⑧ 实验中心   —— 想把「相关」升级成「因果」时用（尚未启用）
  ⑨ 数据质量   —— 数据坏了就不许下强结论
  ⑩ 能力运营   —— 管着「变量表」和「指标定义」本身不要越用越乱
  ⑪ 系统设置   —— 那些决定「多少算够」的数字，摆出来给人看
```

> **链条的意义**：第 ⑦ 步的质量完全取决于第 ①③ 步。经验库里的一条经验，
> 往上追要能追到「哪几条素材、哪段时间、哪些数字、哪个模型版本」。追不动的经验不该被引用。

## 二、11 个功能逐个说

每一节的格式是固定的：
**干什么** → **为什么需要** → **打开会看到什么** → **今天真能做的** → **今天做不到的**

功能程度分三档：
- **可用** —— 有真数据、能端到端走通
- **能用但没数据** —— 功能做完了，但它要吃的数据还没接进来
- **说明页** —— 只是一页文字，明确写着功能未启用

---

### ① 数据接入　`数据 › 数据接入`　**可用**

**干什么**：把广告平台上的投放数字（花了多少钱、多少人看到、多少人点了）弄进系统，
并且建立「平台上那条广告 ↔ 我们库里那条素材」的对应关系。

**为什么需要**：平台给的数据里，一条广告叫 `creative_id: 88213`。
我们库里那条素材叫「春季大促主视觉 v2」。不把这两个对上，
所有数字都只是数字，没法说"是哪条素材的表现"。

**打开会看到什么**：五个标签——数据源（哪些账号接进来了、数据截止到哪天）、
接入向导、字段映射（平台那列叫 `imp`，我们叫「曝光」）、导入批次、同步记录。

**今天真能做的**：
- 上传平台导出的报表 → 配好字段对应 → 导入 → 数字进库
- 同一份报表重复导入会被拦下（按内容比对，不靠文件名）
- 平台上有、但对不上我们素材的广告对象，**进"待匹配"队列，不丢弃**，
  可以在分析素材库里人工认领
- 错误和延迟排在页面最前面，不藏在统计后面

**今天做不到的**：
- **没有平台直连**。只能人工上传报表，不能授权后自动同步。
  ← 这是账号和授权问题，不是代码问题，是整个模块最要紧的缺口
- 只保存了整理后的数据，没保留平台原样返回的那一份

---

### ② 分析素材库　`素材与分析 › 分析素材库`　**可用**

**干什么**：给每一条素材和它的每一个版本一个稳定的身份，
并记住它从哪来、改过几版、哪一版投放过。

**为什么需要**：靠文件名管素材，改一次名字所有历史就断了。
而"哪一版投放过"这件事，决定了投放数字该算到谁头上。

**打开会看到什么**：五个标签——全部素材、待匹配（平台上有但没认领的广告对象）、
待提取（还没做过内容分析的）、特征（六套变量体系长什么样）、版本与血缘。

**今天真能做的**：
- 素材列表、按类型/来源/状态筛选
- 看到一条素材的来源任务和版本关系
- **在"待匹配"里把平台广告对象认领到具体素材版本上**——认领完，投后分析就出数了

**今天做不到的**：
- **看不到素材本身**。没有缩略图、没有预览，只有图标占位。
  素材文件存在另一个已经建好的系统里（媒体资产平台），洞察模块还没接进去
- 因此单素材拆解也做不成"边看视频边看特征"的时间轴形式

---

### ③ 内容分析　`素材与分析 › 内容分析`　**可用（但要人工提供正文）**

**干什么**：把创意内容拆成可以比较的变量。这是整个模块最核心、也最容易被误解的一步。

**为什么需要**：这一步不做，你最多知道"A 比 B 好"；做了才能知道"A 的开场是提问式、B 是场景式"。
**没有这一步，投后分析就退化成一张排行榜。**

**这里有一条硬规矩**：六类素材各有各的一套变量，**不许混用**。
小红书图文的变量是"标题类型/封面构图/生活化程度"，
品牌广告的变量是"叙事结构/品牌资产露出/镜头语言"。
拿视频的"钩子强度"去问一篇公众号文章，得到的答案是没有意义的。

| 六类 | 各自关心什么 |
| --- | --- |
| 小红书图文 | 标题怎么起、封面怎么排、多生活化、话题词 |
| 公众号图文 | 标题与摘要、篇幅结构、产品在第几段出现、引流路径 |
| 品牌广告 | 故事怎么讲、品牌符号露出、镜头与节奏、跨镜头一致性 |
| 数字人 | 口型、表情、手势、语速、背景、**是否标了 AI** |
| 广告前贴 | 首帧、开场结构、单位时间信息量、**静音也能看懂吗** |
| 爆款复刻 | 参考了谁、结构照搬了多少、改写程度、**版权风险** |

**打开会看到什么**：七个标签。前六个是六类素材各自的**特征矩阵**（一行一条素材，
一列一个变量，横着比），第七个是"单素材拆解"（一条素材逐项看）。

**今天真能做的**：
- **AI 自动提特征**（今天刚做完，第 9 批）：在单素材拆解里贴上正文、点按钮，
  模型按这类素材自己那套变量提一遍
- 提出来的每一项**都标着是 AI 提的**，状态停在"待确认"，人要逐项认可或推翻
- **人工的结论单独一行，后台重跑不会覆盖它**
- 每次提取都留全套痕迹：用了哪个指令版本、哪个模型、耗时多久、有没有丢项

**今天做不到的**：
- **正文得人工粘贴**。素材正文不在库里（原因见 ② 的缺口），所以提取时必须手动带上
- **本地环境跑不出真结果**。模型开关没配真实供应商，本地点提取会失败——
  但失败也会完整留痕，这是有意的（宁可失败，不许编一份假的出来）
- 一次只能提一条，没有批量、没有重试队列
- 变量词表（比如"标题类型"允许哪几个值）只能改代码，没有管理界面

---

### ④ 投后分析　`工作 › 投后分析`　**可用（数据是样例）**

**干什么**：投放之后，解释到底发生了什么。

**为什么需要**：这是模块的价值兑现点。前三步都是为它做准备。

**打开会看到什么**：六个标签——指标总览、素材对比、趋势、疲劳、异常、驱动因素。

**今天真能做的**（这一批做的其实不是六张图表，是一套「能不能下结论」的判断）：

- **每个数字旁边都写着它的边界**：数据从哪天到哪天、样本多少、
  用的什么币种和归因方式、误差范围多大
- **算不出来就说"不可用"，不写 0**。（点击率 = 点击 ÷ 曝光，
  曝光是 0 的时候答案不是"0%"，是"这个问题问不出答案"。写成 0 会被读成"表现极差"。）
- **归因分五档**，只有第一档"可归因"表示"这个差异能算到这个变量头上"。
  同时改了两个变量的一对素材，哪怕数字差 80%，也只能标"归不了因"
- **疲劳只列"排除不掉的解释"**。素材看腻了、人群变了、投放量变了、数据延迟了，
  在数字上长得一模一样。**"受众变化"永远列在排除不掉里**——受众数据一条都没接入
- **天数不够时不许说"没问题"**。修过一个真缺陷：3 天数据时后端会返回
  "没有疲劳迹象 + 结论可靠"，读起来是"查过了没事"，而事实是"压根没法查"
- 页面底部固定挂一句：**这里全部是观察到的相关，没有一条是实验证明的因果**

**今天做不到的**：
- **数字来自导入的样例数据，不是真实投放**。四条曲线是刻意设计出来测试算法的
- "驱动因素"目前只够 4 条素材做对照，是能跑的最小规模
- 复盘报告在报告中心做，不在这里

---

### ⑤ 报告中心　`经验与输出 › 报告中心`　**可用**

**干什么**：把散在各处的分析，组织成一份能发给别人看的复盘材料，
确认之后可以把里面站得住的结论沉淀成经验。

**为什么需要**：分析页面是给分析的人看的。要让决策的人用，得有一份写明
"哪个项目、哪段时间、多少样本、数据从哪来"的东西。

**打开会看到什么**：三个标签——全部复盘、待确认、已沉淀经验。

**今天真能做的**：
- 写复盘、确认复盘、从复盘里挑结论沉淀成经验
- 第三个标签专门让**「已确认但一条经验都没沉淀」的报告显出来**——
  确认只表示这份报告写的是真的，不表示有人愿意拿它当下一轮的依据

**今天做不到的**：
- 从复盘一句话直接沉淀出的经验，类型和可靠度是空的
  （后端会落到最保守的"假设/方向性"）。**这是故意的**：
  替录入的人标成"事实"等于伪造依据，要补依据得去经验库单独修订
- 周期报告、自定义报告、导出记录没做——文档里提过，但没有任何需求条目支撑

---

### ⑥ 经验库　`经验与输出 › 经验库`　**可用**（一天里第一个跑通的）

**干什么**：把一次复盘的结论，变成组织能重复使用的经验。

**为什么需要**：经验最大的问题不是没人总结，是**总结完了没人管它有没有过期**。

**打开会看到什么**：五个标签——候选经验、已确认、待复审、已失效、引用记录。

**今天真能做的**：
- 完整的生命周期：待确认 → 已确认 → 待复审 → 已失效，每次变更有审计记录
- **下游默认只能引用"已确认且未失效"的经验**
- 引用的时候必须带上适用条件和来源链接，**不能只把结论拼进提示词**
- 下游用完可以回传"采纳了/改了/拒了"和原因
- 新数据和老经验冲突时，生成待复审提示，**不静默覆盖历史结论**

**今天做不到的**：
- 待复审堆积**不会提醒任何人**。人工复核是这套系统唯一的质量闸门，
  而这个闸门现在没有铃 ← 这是第二要紧的缺口

---

### ⑦ 投前洞察　`工作 › 投前洞察`　**可用**

**干什么**：在素材开始生产之前，把过去验证过的经验摆到决策桌上。

**为什么需要**：整条链最后回流到这里。前面六步全做完，如果做下一版素材的人看不到，等于没做。

**打开会看到什么**：五个标签——策略证据、创意建议、历史模式、风险与反例、引用记录。

**这里有个设计上的关键决定**：洞察卡不是新建的一张表，是**经验库里同一条经验的另一个视角**。
同一条东西，在经验库里是"一条待确认的结论"，在投前洞察里是"能不能拿来当证据的卡"。

**今天真能做的**：
- 每张卡有九个字段，其中最重要的是**「类型」——事实 / 统计观察 / 假设 / 建议**。
  这四个不能混。这是本模块和普通报表工具的根本区别
- 九个字段缺哪个就明说缺哪个，不藏起来
- **跨渠道比较默认关着**，开关长在警告横幅里而不是工具栏里——
  打开它是接受一个前提，不是换个筛选条件
- 数据质量没校验成功时，页面上说的是"**这一次没能校验，这是『不知道』，不是『没问题』**"
- 不用新建任务就能查看和引用；重复引用只增加引用记录，不会把 Brief 越写越长

**今天做不到的**：
- 卡的质量取决于经验库里有多少条真经验，而经验来自复盘，复盘来自真实投放数据。
  **目前这条链的源头是样例数据**

---

### ⑧ 实验中心　`素材与分析 › 实验中心`　**说明页（功能未启用）**

**干什么**：把结论从"看起来相关"提升到"更可信的因果证据"。

**为什么这一页只有文字**：三份文档口径一致——要先建 Experiment、Variant、SampleCheck
三个对象。这不是建三张表的事：**事先约定的样本门槛必须登记在实验对象上**，
事后再定门槛，等于允许"凑够了就说显著"。没有这层约定，
做出来的"实验中心"和现有的素材对比没有区别。

**为什么不留个空壳页**：原先这个入口落在通用模板上，渲染出一个带虚线框和「—」的分析壳子。
那个壳子传达的是"功能在跑，只是这个项目还没数据"，而事实是功能根本不存在。
所以换成一页明确写着"实验能力尚未启用"的说明。

**这一页真正想说的一件事**：事后从已投素材里挑出"只差一个变量"的一对，
和事先设计一次实验，**算出来的数字可以一模一样，但能支撑的说法不同**。
事后挑出来的那一对，本来就是被人选出来投的，这层选择效应排除不掉。
所以现有的"素材对比"最多说到"可归因于这个变量"，再往前的因果说法它撑不住。

---

### ⑨ 数据质量　`治理 › 数据质量`　**可用**

**干什么**：阻止错误的数据产生强结论。

**为什么需要**：数据晚到两天、某个平台漏传一天、两个数据源用了不同的归因窗口——
这些都不会报错，但会让分析结论悄悄跑偏。

**打开会看到什么**：六个标签——新鲜度、缺失、异常、口径、对账、修复队列。

**今天真能做的**：
- 五类检查：数据是不是滞后了、有没有日期空洞、有没有物理上不可能的值
  （点击数 > 曝光数）、几个数据源的口径混了没、花的钱能不能归到素材上
- **任何一个"阻断"级问题存在时，整个模块暂停给强结论**
- 处置状态会**自动翻回来**：标了"已修复"，但数据还在滞后，下一次刷新立刻变成
  "报修后又出现"。没有这个机制，点一次"已修复"就能把问题永久藏起来

**一个设计决定值得你知道**：质量问题**不入库**，每次请求实时算。入库的只有"人做了什么判断"。
如果问题本身也入库，就会出现"库里说坏了、数据说已经好了"这种自相矛盾——
一个数据质量模块最不该有的毛病。

**今天做不到的**：
- 没有外部对账源，只能拿库里的数据互相比
- 没有告警推送（同 ⑥ 的缺口）

---

### ⑩ 能力运营　`治理 › 能力运营`　**可用（只读）**

**干什么**：管着"变量表"和"指标定义"本身，防止越用越乱。

**为什么需要**：同一个概念，这个人填"提问式开场"、那个人填"疑问句开头"，
半年后这个变量就废了——统计的时候它们是两个不同的值。

**打开会看到什么**：五个标签——特征体系、指标字典、分析 Skills、评测集、质量看板。

**今天真能做的**：
- 看到六套变量体系分别有哪些字段、每个字段实际被填了哪些值
- 看到 AI 提取的准确率——但**只统计人工复核过的**，没人看过的一条都不算。
  （把没看过的算成"机器对了"，准确率会随提取量自动上涨，而那个上涨和模型好不好毫无关系。）
  不足 10 条时直接不给数字
- 看到哪些值可能需要合并（但只是候选，不进待办——**把两个真正不同的值合并，比词表碎一点更糟**）

**今天做不到的**：
- **整页只读**。改口径和词表要改代码、过评审。
  存一份治理台账，它迟早会和它治理的数据对不上，而治理面对不上比业务页面对不上更难发现
- 准确率永远只能回答"人看过的那些"，回答不了"整体准确率"

**干什么**：把那些决定"多少算够"的数字摆出来给人看。

**今天真能做的**：看到每个阈值现在是多少、推荐值是多少、它影响什么。

## 四、这份文档怎么用

**读的时候只做一件事：遇到"这不是我想的"就标出来。**

标出来之后分三种处理：

| 情况 | 怎么办 |
| --- | --- |
| 文档写的和你想的不一样 | **改文档**（03/20/22 是权威源），然后代码跟着改 |
| 文档没写、我自己发挥了 | 我把发挥的地方退回来，按你说的重做 |
| 你想的东西文档和代码都没有 | 先写进文档，再排进建设顺序 |

**三套变一套的机制就是这个**：以后你的想法先进文档，我照文档做，
做完用这份说明回来对账。跳过写文档那一步，三个月后又会是三套。

## 五、想要"实感"的话，最快的办法

这份文档解决的是"知道有什么"。要解决"摸得着"，得把服务起起来，
按第一节那张链条图的顺序真点一遍：

```
数据接入 上传一份报表
   → 分析素材库 认领平台对象
      → 内容分析 提一次特征
         → 投后分析 看数字变了
            → 报告中心 写一份复盘
               → 经验库 沉淀一条经验
                  → 投前洞察 看到那条经验变成了一张卡
```

走完这一圈，这个模块在干什么就不再是文字了。
其中"内容分析提特征"这一步在本地会失败（模型没配），但失败也会留痕——
那一步可以看留痕代替。

### 走查中发现的两个问题

**问题 1（小）：素材名乱码。** 分析素材库里有一条 `Nova �ļ����� �����˿ڲ� v1`（已失效状态），
是早期灌演示数据时 GBK 编码的遗留。演示脚本后来加了 `PYTHONUTF8=1` 修掉了根因，这条是脏数据残留。

**问题 2（要紧）：链条最后一环有个断层。**

刚确认的那条经验，在投前洞察里落在「风险与反例」，标着：

> 类型：**假设** · 置信：**方向性** · **没写适用范围**——这条结论没说自己适用于哪里 ·
> 缺 适用范围、数据依据、内容依据、建议动作

而它在经验库里**明明写着**适用条件："巨量引擎信息流；扫拖机器人产品线；单条素材连续投放 7 天以内"。

原因在 `prelaunch.go:91` 的注释里：洞察卡的**适用范围是结构化字段**（渠道 / 创意类型 / 目标，
用来做筛选），经验库里那句是**自由文本的适用条件**，两者是两个字段。

**后果**：经验库的录入界面里没有结构化适用范围的输入项，所以从复盘沉淀出来的经验
**必然**缺这一项。而「策略证据」视图只收「事实 / 统计观察」两类卡，
这些经验类型又必然是「假设」——**两道门都过不去，`策略证据` 视图必然是 0 条**。

这不是 bug（每一步都按设计在跑），是**链条最后一米没接上**：
投前洞察最有价值的那个出口，目前结构上拿不到东西。要接上需要在经验库补两件事——
录入结构化适用范围、以及把类型从「假设」升级到「统计观察」所需要的依据补录入口。
