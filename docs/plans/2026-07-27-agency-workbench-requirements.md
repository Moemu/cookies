## 1. 背景与问题定义

cookies 当前已经形成“需求与策略 → 创意创作 → 素材洞察 → 智能投放 → 经验回流”的产品闭环，并具备 Project 上下文、产物版本、证据引用、ChangeSet、预检和审计等基础能力。

当前体验更适合单品牌、单项目的产品演示。广告代理商通常同时服务多个客户、品牌、Campaign 和广告账户，工作重点还包括批量生产、大模型质检、素材人工检查、跨平台投放、经营汇报和权限隔离。现有页面与流程在这些场景下存在以下核心问题：

1. Project 缺少明确的客户、品牌、Campaign 和广告账户上级关系。
2. 首页以单一当前项目为中心，不能回答代理商当天最紧急的跨客户问题。
3. 新建 Project 只收集名称、品牌和目标，不能建立完整项目边界。
4. 创意任务缺少批量筛选、批量分配、批量质检、批量人工检查和批量交付。
5. 创意评审页面与实际内容语义错位，缺少真实素材评审能力。
6. 成员与职责只有抽象角色，没有真实成员、客户方成员和权限范围。
7. 资产版本页不能回答版本差异、人工确认范围、使用位置和授权期限。
8. 广告账户页与实际内容语义错位，不能证明动作会写入哪个平台账户。
9. 素材进入投放前缺少统一的大模型质检结果和人工检查确认记录。
10. 页面切换过程中会短暂显示错误 Project、空数据和 `v0.0`，存在误操作风险。
11. 不同页面对项目阶段和进度的计算结果不一致。
12. 缺少跨客户的交付、预算、SLA、团队负载和效果汇报视图。

### 1.1 产品判断

本计划不新增第五个业务系统，也不改变 Project 是四系统共同上下文的既有决策。

目标是在 Project 上方增加代理商业务所需的客户层级，在 Project 内补齐批量生产、质量检查、账户安全和版本追溯能力：

```text
Organization
└── Client
    └── Brand
        └── Project / Campaign
            ├── Strategy Workspace
            ├── Creative Tasks and Assets
            ├── Insight and Reports
            └── Delivery Plans and Ad Accounts
```

其中：

- `Organization` 是代理商组织与权限边界。
- `Client` 是客户资料、品牌资产和经营汇总边界，不代表客户需要登录平台。
- `Brand` 是品牌规则、资产、授权和知识复用边界。
- `Project` 继续作为四系统共同引用的执行上下文。
- `Campaign` 在 MVP 中作为 Project 的业务类型或可选外部标识，不立即引入与 Project 并列的第二套流程容器。

## 2. 目标与非目标

### 2.1 业务目标

1. 让代理商项目经理在一个首页判断跨客户的待办、风险、素材检查和交付。
2. 降低跨客户、跨品牌、跨广告账户误操作的概率。
3. 缩短从客户 Brief 到可投放创意的准备时间。
4. 支持同一 Campaign 下的多渠道、多规格、多版本批量生产。
5. 建立“大模型质检 → 广告素材人工检查确认 → 投放使用”的简洁质量门禁。
6. 让人工确认版本、实际投放版本和最新工作版本保持可追溯关系。
7. 支持代理商按客户、品牌、负责人、平台和时间范围输出经营与效果报告。

### 2.2 用户体验目标

- 用户始终知道当前操作属于哪个客户、品牌、Project 和广告账户。
- 页面加载期间不显示其他 Project 或默认占位 Project 的业务数据。
- 首页第一视觉落点是需要处理的工作，而不是产品模块入口。
- 批量工作不要求逐个打开任务或素材。
- 素材检查页先展示预览和大模型质检问题，再展示人工确认按钮。
- 平台用户均为代理商内部人员，客户沟通继续通过现有外部渠道完成。

### 2.3 非目标

- 本计划不实现真实广告平台写入，真实执行仍需单独的连接器和安全评审。
- 本计划不替代现有四个业务系统，也不新增“代理商系统”侧栏。
- P0 不实现完整 CRM、合同、报价、开票和财务结算。
- P0 不实现移动端或平板布局。
- P0 不实现跨组织共享素材，跨客户引用默认禁止。
- P0 不建设客户账号、客户门户、公开评审链接或外部审批能力。

## 3. 用户角色与核心任务

| 角色 | 核心任务 | 最关心的信息 | 典型风险 |
| --- | --- | --- | --- |
| 代理商项目经理 | 管理客户、排期、交付、素材检查和资源 | 今日待办、逾期、客户反馈、交付状态、团队负载 | 漏交付、错客户、检查超时 |
| 策略人员 | 整理 Brief、研究证据和策略方案 | 客户目标、历史结论、确认范围、策略版本 | 使用过期信息、结论无依据 |
| 创意负责人 | 拆任务、分配制作、运行质检和组织人工检查 | 渠道规格、素材版本、负责人、截止时间 | 批量效率低、版本混乱 |
| 设计/制作 | 完成素材和修改 | 明确需求、修改清单、参考资产、截止时间 | 反复修改、反馈不清 |
| 广告投手 | 绑定账户、计划、预算并执行 | 账户、预算、素材人工确认状态、追踪和风险 | 错账户、超预算、使用未确认素材 |
| 数据分析 | 分析素材和投放表现 | 指标口径、素材血缘、实验条件、数据新鲜度 | 归因错误、跨平台口径不一致 |
| 素材检查确认人 | 检查大模型质检结果并确认可用版本 | 素材预览、问题项、版本、渠道规格 | 漏检问题、确认错误版本 |
| 组织管理员 | 管理成员、角色、客户和平台权限 | 权限范围、账户状态、审计和异常 | 越权访问、离职账号残留 |

## 4. 目标信息架构

### 4.1 L0 全局顶栏

顶栏保留 cookies 标志、业务系统切换、全局搜索、任务、素材检查、通知和用户入口，并调整上下文切换器：

```text
[Organization] / [Client] / [Brand] / [Project] / [System]
```

交互规则：

1. Organization 对大多数用户默认固定，只有多组织用户可切换。
2. Client 和 Brand 可搜索、收藏并显示最近访问。
3. Project 列表必须按 Client / Brand 分组，不能继续全量平铺。
4. 进入 Project 后，系统切换保持 Project 不变。
5. 切换 Project 时优先恢复目标 Project 在当前系统内的最近页面。
6. 有未保存内容时，切换上下文前必须提示保存、放弃或取消。
7. 当前页面涉及真实账户或预算动作时，顶栏额外显示平台和账户短标识。

### 4.2 Home

Home 从“当前项目介绍页”调整为“代理商客户组合工作台”，只聚合跨项目信息，不允许直接生成、人工确认或执行。

推荐结构：

1. 主区：今日需要处理。
2. 次区：临期交付与待人工检查素材。
3. 辅助区：客户/品牌健康状态、团队负载、账户异常。
4. 下钻区：最近 Project 和保存视图。

四个系统入口保留在顶栏，不再作为 Home 主内容。

### 4.3 Project Home

Project Home 继续作为单个 Project 的唯一总工作台，展示：

1. 当前阶段和下一步。
2. 关键阻塞及责任人。
3. 四系统最新产物和交接状态。
4. 当前待质检、待人工确认、账户异常和交付风险。
5. 最近活动和审计入口。

### 4.4 跨项目工作区与单项目工作区

- Home、全局任务、全局素材检查和组织级报告允许“全部 Project”。
- 策略生成、创意编辑、素材确认和投放执行必须绑定一个 Project。
- 涉及广告平台动作时还必须绑定一个明确广告账户。
- 跨项目列表进入对象详情后，页面必须显示完整客户和 Project 上下文。

### 5.2 上下文不变量

以下规则必须由服务端校验，不能只依赖前端：

1. Brand 必须属于 Client。
2. Project 必须属于当前 Organization、Client 和 Brand。
3. AdAccountBinding 必须属于同一 Client，跨客户绑定默认拒绝。
4. 任务、产物、质检、人工确认、ChangeSet 和审计事件必须属于同一 Project。
5. 人工确认必须引用同一素材版本最近一次完成的大模型质检。
6. 执行动作引用的素材版本必须是人工确认版本，且使用范围覆盖目标平台和规格。
7. 素材产生新版本后，旧版本的人工确认不自动继承。
8. 任何跨 Project 引用必须保留来源 Project、版本和授权依据。

## 6. 详细需求拆分

## Epic A：客户组合工作台

### A1. 客户与品牌导航

**用户故事**

作为代理商项目经理，我希望按客户和品牌组织 Project，以便快速切换工作且避免进入错误客户上下文。

**功能需求**

- [ ] `AG-HOME-001` 顶栏 Project 切换器按 Client / Brand 分组。
- [ ] `AG-HOME-002` 支持搜索客户、品牌、Project 名称、代码和负责人。
- [ ] `AG-HOME-003` 支持最近访问和收藏 Project。
- [ ] `AG-HOME-004` 切换菜单显示 Project 状态、阶段、负责人和最近更新时间。
- [ ] `AG-HOME-005` 客户或品牌归档后不出现在默认列表，但可在归档筛选中查看。
- [ ] `AG-HOME-006` 无权访问的客户、品牌和 Project 不出现在搜索和切换结果中。

**验收标准**

1. 拥有 50 个以上 Project 时，用户无需滚动完整列表即可搜索定位。
2. 相同名称的 Project 必须通过客户、品牌和代码区分。
3. 从系统页面切换 Project 后，系统类型保持不变。
4. 切换后不得出现上一个 Project 的标题、预算、版本或任务。

### A2. 今日需要处理

**功能需求**

- [ ] `AG-HOME-010` 聚合待我处理、待人工检查、即将逾期和异常四类工作。
- [ ] `AG-HOME-011` 每条记录显示客户、Project、对象、优先级、责任人和截止时间。
- [ ] `AG-HOME-012` 默认按业务风险和截止时间排序。
- [ ] `AG-HOME-013` 支持按客户、负责人、业务系统、状态和截止时间筛选。
- [ ] `AG-HOME-014` 支持保存个人视图。
- [ ] `AG-HOME-015` 点击记录进入绑定 Project 的具体对象，不停留在泛化模块首页。

**排序建议**

```text
已逾期
> 账户/预算/合规异常
> 今日到期的素材检查或交付
> 阻塞下游的内部任务
> 普通待办
```

### A3. 客户与项目健康状态

- [ ] `AG-HOME-020` 展示进行中 Project 数、逾期交付数、待人工确认素材数和账户异常数。
- [ ] `AG-HOME-021` 健康状态必须由明确规则计算，并提供原因下钻。
- [ ] `AG-HOME-022` 状态不能只用红、黄、绿表达，必须同时显示文字和图标。
- [ ] `AG-HOME-023` P0 不展示无法解释的综合 AI 分数。

## Epic B：Project 创建与初始化

### B1. 创建入口

- [ ] `AG-CREATE-001` 支持新建空白 Project。
- [ ] `AG-CREATE-002` 支持从组织模板创建。
- [ ] `AG-CREATE-003` 支持复制同品牌历史 Project。
- [ ] `AG-CREATE-004` 支持从客户 Brief 或结构化文件导入草稿信息。
- [ ] `AG-CREATE-005` 复制时必须显式选择是否带入成员、品牌资产、渠道规格、质检规则和账户绑定。
- [ ] `AG-CREATE-006` 历史任务、人工确认记录、真实预算和审计记录不得被复制。

### B2. 四步初始化流程

#### 第一步：客户与项目

- 客户。
- 品牌或产品线。
- Project 名称和代码。
- Project 类型。
- 项目经理。
- 项目周期。

#### 第二步：范围与目标

- 业务目标和成功指标。
- 市场与地区。
- 目标受众。
- 渠道与交付类型。
- 预算基线、币种和时区。

#### 第三步：资源绑定

- 广告账户。
- 落地页、商品、像素和转化事件。
- 品牌资产库。
- 历史策略、素材和经验。

#### 第四步：协作治理

- 代理商内部成员。
- 素材负责人。
- 素材检查确认人。
- 大模型质检规则。
- 高风险动作授权规则。

### B3. 创建校验

- [ ] `AG-CREATE-020` Client、Brand、Project 名称、负责人和周期为必填。
- [ ] `AG-CREATE-021` 投放类 Project 必须至少绑定一个广告账户或明确标记“稍后绑定”。
- [ ] `AG-CREATE-022` 币种和时区冲突时提示影响，不静默转换。
- [ ] `AG-CREATE-023` Project 代码在 Organization 内唯一。
- [ ] `AG-CREATE-024` 创建前展示摘要和缺失项。
- [ ] `AG-CREATE-025` 创建请求支持幂等，重复提交不能生成两个 Project。

### B4. 创建完成状态

创建后进入 Project Home，并显示：

1. 已完成的初始化项。
2. 尚未完成但不阻塞的配置。
3. 阻塞第一个业务动作的缺失项。
4. 推荐下一步和责任人。

## 7. 状态机

### 7.1 创意任务状态

```text
draft
→ ready
→ in_progress
→ model_quality_check
→ human_check
→ confirmed
→ delivered
→ archived
```

异常分支：

```text
in_progress → blocked
model_quality_check → quality_check_error
human_check → changes_required
任意可执行状态 → failed
```

规则：

- `confirmed` 只表示当前版本已由代理商内部人员检查确认。
- `delivered` 必须绑定交付版本和交付记录。
- `failed` 必须包含可理解原因和恢复动作。

### 7.2 大模型质检状态

```text
queued
→ running
→ passed | issues_found | error
```

`passed` 和 `issues_found` 均进入人工检查；`error` 表示质检未完成，需要重试后才能人工确认。

### 7.3 人工检查确认状态

```text
pending
→ confirmed | changes_required
```

新版本产生后始终回到 `pending` 之前的大模型质检阶段。

### 7.4 投放计划状态

```text
draft
→ validating
→ validation_failed | ready_for_confirmation
→ confirmed_for_execution
→ scheduled | executing
→ active
→ completed | paused | failed | result_unknown
```

## 8. 通知与 SLA

### 8.1 通知事件

- 被分配任务。
- 截止时间变化。
- 大模型质检完成、不通过或运行失败。
- 广告素材待人工检查。
- 人工检查确认或要求修改。
- 评论提及或修改项分配。
- 生成、渲染或执行失败。
- 广告账户权限、登录或追踪异常。
- 授权即将到期。
- ChangeSet 预检、执行、失败或回滚。

### 8.2 通知原则

- 页面内通知、任务中心和外部通知共享同一事件，不分别生成重复记录。
- 同类高频事件允许聚合。
- 高风险执行事件不能仅通过低优先级通知传达。
- 用户可配置普通通知，高风险和安全通知不可全部关闭。

### 8.3 SLA

- 人工检查任务可配置截止时间。
- 到期前按规则提醒。
- 逾期后提醒素材检查确认人和项目经理。
- SLA 暂停、恢复和延期必须记录原因。

## 10. 审计与安全

## 16. 迁移策略

### 16.1 现有 Project 迁移

1. 创建默认 Client：`未分类客户`。
2. 根据现有 `brand` 字段创建或关联 Brand。
3. 将现有 Project 绑定到默认 Client 和对应 Brand。
4. 不改变现有 Project ID 和业务对象关系。
5. 首次进入时提示管理员补齐客户负责人、周期、市场和质检规则。

### 16.2 现有确认与版本

- 无明确确认人的历史“已确认”记录标记为 `legacy_confirmed`。
- 历史记录不可伪造真实确认人或大模型质检结果。
- 现有创意产物默认作为 `workingVersion`。
- 只有存在明确人工确认事件时才设置 `humanConfirmedVersion`。
- 现有投放模拟保持模拟标识，不迁移为真实执行记录。

### 16.3 渐进发布

- 使用功能开关按 Organization 开启客户层级。
- 先迁移只读视图，再启用写入。
- 新旧 Project 切换器短期可并行，但同一用户会话只使用一种。
- 写入新模型后保留回滚读取能力，禁止双写产生两个事实源。

## 18. Definition of Done

每个需求进入完成状态前必须满足：

1. 页面、对象和操作语义一致。
2. 默认、加载、空、错误、权限不足、过期和部分失败状态齐全。
3. 服务端完成 Organization、Client、Brand、Project 和对象范围校验。
4. 关键写入具备幂等、并发保护和审计。

6. 键盘、焦点、语义名称和状态表达满足 WCAG 2.2 AA 基线。
7. 使用真实长度客户名、Project 名、任务名和多语言混排验证。
