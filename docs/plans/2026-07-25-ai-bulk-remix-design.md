# AI Bulk Remix Design

## 目标

在新版素材库中支持从大量视频素材里创建 AI 混剪草案。用户把素材分配到前段、中段、后段，每段可选择多个视频；系统生成可解释的时间线草案，后续可接入 RenderJob/FFmpeg 做真实合成。

## 核心逻辑

混剪分为三个叙事段：

- 前段：负责 0-3 秒吸引注意力，优先选择短、强视觉、近上传、竖版或高信息密度素材。
- 中段：负责展示过程、卖点、冲突或证明，优先选择多来源、多比例、多时长素材，避免连续重复。
- 后段：负责收束、CTA、品牌记忆或结果展示，优先选择画面稳定、尺寸完整、来源可信的素材。

MVP 不直接调用大模型生成不可控剪辑，而是使用确定性 AI planner 输出结构化草案。planner 对每个候选素材计算 segment score，再按目标时长预算选片，输出每个 clip 的估算时长、入点、出点、选择理由和风险提示。后续接入多模态理解后，只替换候选特征，不改页面与时间线协议。

## 数据流

1. 前端从素材库读取项目资产，筛选 ready + video MIME 的素材。
2. 用户把素材加入前/中/后三段，支持搜索、批量选择和跨段调整。
3. 用户选择目标时长和节奏风格。
4. `buildBulkRemixPlan()` 生成时间线草案。
5. 页面展示三段时间线、总时长、覆盖率、选择理由和缺口警告。
6. 后续版本把草案提交给后端保存为 TimelineVersion，再创建 RenderJob。

## 评分策略

每个候选素材的分数由以下信号组成：

- 新鲜度：越新的素材权重越高。
- 来源：`captured` 和 `provider_generated` 更适合前段钩子，`upload` 更适合收束。
- 比例：竖版更适合短视频快节奏，横版更适合叙事解释。
- 尺寸完整度：有宽高记录的素材更可信。
- 大小估算：用文件大小估算可用片长，后续替换为真实 duration。
- 去重：同段内避免重复 asset，连续 clip 尽量避免相同来源和相同比例。

## 输出协议

Planner 输出 `BulkRemixPlan`：

- `segments`：前/中/后三段，每段包含预算、实际时长、clip 列表。
- `clips`：包含素材引用、展示标签、估算时长、入点、出点、分数、选择理由。
- `warnings`：提示素材不足、某段为空、目标时长无法满足、当前使用估算时长。
- `summary`：总时长、使用素材数、目标达成率、风格说明。

## MVP 边界

- 不做真实转码、裁剪和导出。
- 不上传视频文件格式扩展，先消费已有素材库返回的视频资产。
- 不引入外部 AI 调用，先用可解释规则实现稳定 planner。
- 不修改 Go 后端数据库模型，避免在视频资产字段未完善前做错误迁移。

## 飞书 Base 资料洞察

`【日进一斗】广告商业化技术学习资料` 中可纳入项目的方向：

- 广告 AIGC 工业化创编闭环：把混剪从一次性生成升级为素材选择、质检、回流和持续优化。
- 素材工坊到内容引擎：把素材库、planner、草案历史、渲染任务和效果回流串成内容生产链路。
- 多模态语义引擎：用场景、人物、商品、动作、情绪、卖点等标签替换当前文件大小与画幅估算。
- 广告智能体工作流：将选素材、生成草案、提交渲染、诊断失败和重剪封装为可编排 Agent。
- 知识中枢与 RAG：把学习资料沉淀为策略依据，辅助生成混剪 prompt、评分解释和安全规则。
- 数据反馈飞轮：记录草案、渲染、人工评分和投放表现，沉淀可评估、可训练的数据资产。
- 安全与合规治理：在导出前检查版权来源、违规风险、相似度风险和审核状态。

## 后续演进

- Assets 增加 duration、fps、codec、poster frame、scene embedding。
- Provider 增加视频理解任务，产出人物、场景、情绪、动作和高光区间。
- Creative 增加 `remix.timeline.create` 能力，保存 TimelineVersion。
- RenderJob 根据 timeline 生成视频，输出再进入素材库并写入 provenance。
- RenderJob 首阶段先实现真实 API 与任务生命周期，渲染 worker 可后接 FFmpeg 或云端视频合成。
- Planner 第二阶段接入素材理解标签和历史反馈分，替换当前 heuristic score。
