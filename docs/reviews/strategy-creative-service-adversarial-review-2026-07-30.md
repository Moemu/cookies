# Strategy → 创意任务策略：反方评审与自我修正

日期：2026-07-30
评审结论：在“Strategy 内可独立使用、人工导出交接 Creative”的范围内可用；不应宣称已经具备 Creative 自动生产闭环。

## 1. 反方结论

最强反对意见不是“功能不够多”，而是以下四种伪可用：

1. 卡片写着推荐排名，实际仍按目录顺序展示。
2. 看到素材 ID 就声称模型理解了图片或视频。
3. 输出字段都有内容，但内容只是字段说明或通用模板。
4. 新数据跑通，历史数据刷新却白屏。

本轮验收实际复现了第 4 类问题：真实模型将空 `claims_and_evidence` 返回为 `null`，前端直接访问 `items.length` 导致 React 根节点卸载。修复后，服务端对新旧策略统一规范化全部集合，前端媒体字段也做向后兼容。

## 2. 已发现问题、风险和处理

| 问题 | 风险 | 修正 |
| --- | --- | --- |
| 推荐卡按目录顺序 | 用户误以为首项是 Top 1 | 前端按推荐 rank 排序 |
| “转化”泛化命中游戏业务 | 饮料 Brief 被错误推荐游戏前贴 | 增加行业、渠道、语境等资格门 |
| 未识别目标默认品牌曝光 | 缺失事实被系统猜测 | 目标缺失保持 `unknown` |
| Knowledge 引用被当成参考视频 | 文档引用制造虚假素材信号 | 不把无类型引用解释为视频 |
| 素材引用可手填 | 跨项目、错版本和未 ready 素材进入生成 | 改为当前 Project 素材选择器并由后端复核 |
| 图片/视频存在即当成内容证据 | 策略声称看过实际未分析的内容 | 分成 semantic / production_only / unavailable |
| 业务策略复述字段说明 | 输出看似完整但无法开工 | 各业务增加确定性派生逻辑，并拒绝说明文本原样作为值 |
| 只有一个通用假设 | 策略深度不足 | 归一化保证至少两个可验证假设 |
| 列表接口只返回 Plan 摘要 | 刷新后已生成结果消失 | 按更新时间排序并 hydrate Profile、CurrentStrategy |
| 模型空数组返回 `null` | 契约失败和前端白屏 | 新生成与历史读取都统一规范化为 `[]` |
| 生成期间仍能编辑 | 页面答案与冻结上下文分叉 | 生成期间禁用问题输入 |
| 删除答案无法被识别为未保存 | 用户无法真正清空已有答案 | 比较键是否存在，并发送 remove 操作 |
| 旧推荐计划仍写“来自推荐” | 政策变化被掩盖 | 对照当前政策显示历史推荐变化 |

## 3. 对“图片视频有用”的反驳

反方意见：

> 既然页面已经选了图片和视频，为什么不能直接用它们做策略？

回答：

素材存在只能证明“有一个可访问文件”，不能证明系统已经理解内容。允许把未分析素材写进语义策略，会制造高置信度幻觉。

因此当前设计宁可少用，也不假装使用：

- 有 Feature：可使用已记录语义观察。
- 无 Feature：只用于生产准备和规格校验。
- 页面预览：帮助人确认素材选择，但预览本身不等于服务端模型读过素材。

该限制降低了自动化程度，但显著提高事实可信度。

## 4. 对“策略够不够深”的反驳

反方意见：

> 只问几个问题再生成 JSON，可能只是换了一个模板。

验收标准不是字段数量，而是：

- 业务专属字段是否使用了 Brief 和用户答案。
- 是否形成至少两个可以用不同变量验证的假设。
- 是否把证据与未知项分开。
- 是否有对素材、权利和生产条件的真实边界。
- 是否禁止越界生成脚本、镜头和模型 Prompt。

真实电商案例已能根据用户填写的卖点优先级、优惠事实、CTA、商品图和主视频，输出转化主张、信息顺序、开场机制和商品保真要求；同时明确两个素材没有语义分析，未把画面内容写进策略。

## 5. 仍未消除的风险

### 5.1 目录会过期

Strategy 目录只表示业务知识，不表示 Creative 实时能生产。需要业务 Owner 定期评审 Profile；未来若要承诺运行时可用，应增加独立的 Creative availability 契约。

### 5.2 规则权重仍是人工判断

当前分数只做稳定排序，不是效果预测。必须用用户覆盖率、真实开工反馈和后续效果数据校准，不能把高分解释成高成功率。

### 5.3 素材语义分析依赖上游

服务支持读取 AssetFeature，但当前示例素材没有 Feature，因此只能做到规格级使用。若实际业务要求内容级推荐，需要上游素材分析稳定产出版本化特征。

### 5.4 外部参考视频仍不可自动理解

当前不抓取 URL，爆款复刻可依赖用户描述和机制选择，但不能宣称系统已看过外部视频。要增加自动分析，必须先同时解决 SSRF、下载、版权、隐私、内容安全和特征版本问题。

### 5.5 仍是人工交接

Markdown 能让 Strategy 流程独立可用，但不能证明 Creative 系统已自动消费。自动 Handoff 必须另建显式、版本化、可审计契约，不能让 Strategy 直接写 Creative 表。

## 6. 发布判断

### 可以发布的范围

- Strategy 工作区内做业务推荐与自由选择。
- 收集业务增量问题。
- 读取当前 Project 素材及其已存在的语义特征。
- 生成、展示、恢复和导出任务策略。
- 人工把 Markdown 交给 Creative 开工。

### 不可宣传的能力

- Creative 运行时一定可用。
- 系统已经理解所有选择的图片或视频。
- 外部参考视频无需授权。
- 已自动创建 Creative 任务或生产成品。
- 推荐分数代表效果概率。

### 后续 Go/No-Go

进入自动 Creative Handoff 前，至少满足：

1. 三类代表性业务的真实任务被 Creative 评审为可开工。
2. 记录并降低 Creative 仍需追问的问题。
3. 素材 Feature 的覆盖率和失败回退可观测。
4. 推荐假阳性、假阴性有固定回归集。
5. 跨模块契约、幂等、版本和失败恢复设计完成。

在上述条件之前，保持当前“Strategy 真实可用、Creative 人工交接”的边界最稳妥。
