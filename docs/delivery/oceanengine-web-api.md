# OceanEngine Web API driver

The driver ID is `oceanengine-web-api/session/v1`.

The driver uses the organization Connector session. It does not require Edge,
CDP, screenshots, or page selectors. Historical runs use
`playwright-rpa/edge/v3` when they have no stored driver.

## Frozen observations

- The inspected Secsdk version is `1.2.22`.
- `TOKEN_PATH` is undefined.
- The CSRF HEAD uses the protected POST path.
- HEAD sends `x-secsdk-csrf-request: 1`.
- HEAD sends `x-secsdk-csrf-version: 1.2.22`.
- The server returns `x-ware-csrf-token`.
- POST sends `x-secsdk-csrf-token`.

The static platform build and the sanitized HAR exposed these exact paths:

- `POST /superior/api/v2/project/create`
- `POST /superior/api/v2/promotion/create_promotion`
- `GET /superior/api/v2/project/detail`
- `GET /superior/api/ad/promotion/detail`

Both captured browser writes included the `_signature` query parameter. They
also included `x-sessionid`, `x-csrftoken`, and the Secsdk CSRF header. This
proves presence only. It does not prove that the server requires every field.

The public platform bundle shows the field sources. Its request interceptor
sets `X-SessionId` from `window.sessionId`. Its URL transformer calls an
obfuscated `sign({url, body})` module and adds `_signature`. The transformer
handles same-origin GET requests and supported POST content types. This is
browser-client enrichment. It is not evidence of a server requirement.

The existing Connector omits `_signature` and `x-sessionid` for multiple live
read-only GET and POST routes. The write Client must omit both fields first.
Add a field only after an isolated experiment proves that the server requires
it. Do not infer a write requirement from the browser request alone.

The HAR included write request bodies. It did not include response bodies.
Only field names and JSON types are stored in Git. The contract fixture has the
state `request_captured_response_pending`.

## Controlled direct-HTTP probe

The 2026-08-31 direct-HTTP probe omitted `_signature` and `x-sessionid`. The
Client sent no project POST. Its protected-path HEAD returned HTTP 200 without
`x-ware-csrf-token`, so the Client stopped before constructing the write.
A read-only reconciliation query found no object with the probe name digest.

The source confirms that Secsdk sends HEAD to the protected pathname without
the `aadvid` query parameter. The write Client now follows this behavior. The
server still did not issue a token to the Connector HTTP session.

The same HEAD was then sent from the declared, signed-in Edge page. It also
returned HTTP 200 without `x-ware-csrf-token`. This rules out Connector Cookie,
Go TLS, and browser fingerprint differences for that request. The next check is
the Secsdk in-memory token cache. It must inspect metadata only and must not
export the token value. Do not retry the project POST.

The exact Secsdk `fetchTokenFromServer` call returned its official `DOWNGRADE`
result. The sanitized HAR then proved that both captured browser writes sent
`x-secsdk-csrf-token: DOWNGRADE` and received HTTP 200. Secsdk 1.2.22 explicitly
adds this value before it calls the native browser transport. Therefore,
`DOWNGRADE` is the observed browser protocol for this account. It is not an
unknown signature or a generated bypass value.

The production write Client still rejects `DOWNGRADE`. The probe can use it
only with an explicit command flag and an exact one-write confirmation. This is
a product policy. It is not a discovered platform requirement.

The operator approved one probe-only fallback write. The Client sent one POST
with `DOWNGRADE` and omitted `_signature` and `x-sessionid`. The platform
returned HTTP 200 with business code `50100`, which the platform bundle names
`INTERNAL_SERVICE_ERROR`. Reconciliation found no project. The result is a
deterministic rejection, not an uncertain transport result. Do not retry it.
The next experiment must add only one browser field and requires new approval.

The public source map identifies the signer as `@byted/acrawler@1.6.8`. Its
runtime exports `sign` and `dfp`. The package is absent from the public npm
registry, but the published runtime executes without DOM objects in Node.js.
The signer accepts the exact URL and normalized POST body. Tests show that the
result changes with URL or body content. Object key order does not change it.
The same process returns the same result for the same input. Fixed module-load
time produces the same result across processes. A different load time changes
the result. This shows that the signature contains load-time clock state. No
test found account, Cookie, DOM, or device input. Do not reuse a signature from
an old request.

The platform request interceptor gets `x-sessionid` from `window.sessionId`.
The create-page bundle initializes this global with `uuid@8.3.2` UUID v4. It
uses browser cryptographic randomness. The two captured write requests used
different valid UUID v4 values. The current project-management page does not
define the global. This field is request-page state. It is not an account token.
Treat its value as session data. Do not log it or store it in a fixture.

The probe supports `--with-session-id`. It generates a new UUID v4 in memory.
It sends the field only with an executing, explicitly enabled downgrade probe.
The production adapter leaves this option empty. No new write is authorized by
this research or by the existence of the option.

## Release gates

`COOKIES_OCEAN_ENGINE_WEB_API_WRITE_ENABLED` defaults to `false`.
`COOKIES_OCEAN_ENGINE_WEB_API_WRITE_ACCOUNT_ALLOWLIST` must also contain the
exact external account ID. The current adapter blocks Submit before it consumes
the one-time confirmation token because response and reconciliation contracts
are not captured.

The 2026-08-31 probe used a dedicated test account, future dates, and the
minimum controlled budget. The operator deleted both objects after capture.
Continue controlled research on the two optional browser fields. Keep Prepare
and read-only research available. Production writes must not use `DOWNGRADE`
unless the product policy changes explicitly.
