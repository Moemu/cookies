## 1. 技术基线

- 后端：Golang 模块化单体起步，四系统和共享基座保持包、Schema、迁移、API 与事件边界。
- 前端：React + TypeScript，全局 Shell、四系统和 Design System 分层。
- 业务数据：PostgreSQL；缓存/短期协调：Redis；异步任务/事件使用可靠消息设施。
- 二进制：对象存储；知识：ORAG + PostgreSQL + Qdrant。
- 模型：统一 Provider Gateway，默认火山引擎。

具体框架、队列和云资源在 ADR 中选定；业务代码不得直接依赖云厂商基础资源类型。

## 2. 环境与配置

环境至少分为 `local`、`test`、`staging`、`production`，账户、数据库、Bucket、密钥和 Provider 凭据完全隔离。

- 配置通过环境/配置中心注入并经过 Schema 校验，不提交 `.env` 和真实密钥。
- 密钥使用 Secret Manager/KMS，支持轮换、版本、访问审计和紧急撤销。
- 测试环境默认使用脱敏/合成数据，不复制生产客户内容。
- 生产调试访问需临时授权、工单理由和完整审计。

## 3. CI/CD 与发布

每次变更至少执行格式化、静态检查、单元测试、Schema/迁移、OpenAPI/事件契约、依赖漏洞和 Secret 扫描。

- 数据库迁移向前兼容，采用 expand/migrate/contract，禁止应用启动时无控制自动执行破坏性迁移。
- Provider、Skill、平台 Skill 和 ORAG 升级运行固定评测与 Consumer Contract。
- 使用 Feature Flag/组织白名单灰度；Flag 有 Owner、到期时间和清理任务。
- 发布记录代码、配置、Schema、Skill、模型别名和依赖版本。
- 回滚不能依赖不可逆数据删除；必要时执行前向修复。

## 4. 数据库与多租户

- 所有租户业务表包含 `organization_id`，索引和唯一约束将其作为前缀或组成部分。
- Repository 默认注入租户上下文，禁止调用方任意省略；跨租户运维使用独立受审计通道。
- 四系统使用独立 Schema/迁移目录；共享基座不能通过公共查询绕过数据所有权。
- 金额、时间、状态、版本、软删除和审计字段使用统一类型规范。
- 大表定义分区、归档、索引和查询预算，后台任务使用游标而非全表加载。

## 5. 可靠消息与任务

- 业务事件通过事务 Outbox 发布，至少一次投递。
- 消费者保存幂等记录、处理状态和来源版本。
- 重试采用分类退避；不可重试错误进入死信和人工修复。
- 长任务记录心跳、检查点、取消和补偿；任务执行器宕机可恢复。
- 队列按 Organization 和能力限流，避免单租户耗尽公共资源。

## 6. SLO 与容量

MVP 初始目标：

| 服务 | 可用性 | 延迟/恢复目标 |
| --- | --- | --- |
| 身份、项目、草稿读取 | 99.9% 月可用性 | 常规读取 P95 < 500ms |
| 业务写 API | 99.9% | P95 < 1s，不含异步生成 |
| Agent/模型/媒体 Job | 99.5% 接受任务 | 5 秒内可见排队/运行状态 |
| 投放审批与暂停 | 99.9% | 审批状态 P95 < 1s，暂停按平台能力验证 |
| 知识查询 | 99.5% | P95 目标由评测集分层 |

容量模型至少记录活跃组织/用户、项目、素材数量与大小、指标日增量、并发 Agent、模型/媒体 Job、Browser RPA 设备和事件吞吐。上线前通过压测确认限流、降级和成本。

## 7. 备份、RPO/RTO 与灾备

MVP 建议目标：

- PostgreSQL：RPO ≤ 15 分钟，核心服务 RTO ≤ 4 小时。
- 对象存储：启用版本/跨故障域保护，元数据恢复后可对账重建派生文件。
- Qdrant 索引可由知识源重建，但需备份配置、映射和评测数据。
- 审计和审批记录采用不可静默修改的备份/留存策略。

至少每季度执行数据库恢复、对象对账、队列积压、Provider/ORAG 故障和 Browser RPA Kill Switch 演练。正式目标由业务影响分析确认。

## 8. 可观测性与事件响应

- 日志、指标、Trace 统一关联 request、organization、project、task 和业务资源；敏感内容默认不进日志。
- 告警按用户影响、数据风险、外部花费和恢复动作分级。
- Dashboard 覆盖 API、数据库、队列、Provider、ORAG、Connector、媒体 Job 和 Browser RPA。
- 安全或预算事故支持立即禁用 Provider、Skill、Connector 或平台写操作。
- 事件结束后输出时间线、影响、根因、修复、补偿和防复发任务。

## 9. 安全威胁模型

重点威胁：跨租户访问、凭据泄露、Prompt/页面注入、恶意上传、供应链依赖、Browser RPA 越权、重复外部写入和审计篡改。

- 身份、授权、租户隔离在服务端强制执行。
- 用户文档、网页、模型输出和 Tool 返回都是不可信输入。
- 上传执行扫描，脚本/Worker 隔离，出站网络最小化。
- 高风险动作绑定内容哈希、审批人、额度和有效期。
- Secret、Token、Cookie、密码和验证码不进入日志、聊天或截图元数据。
- 依赖锁版本、生成 SBOM、扫描漏洞并制定高危修复 SLA。

## 10. 数据与 AI 合规

- 数据分级：公开、内部、机密、高敏；每级定义访问、日志、模型输入、导出和留存规则。
- 用户上传和客户数据默认不用于训练公共模型。
- 生成内容保存模型/版本、来源素材、权利元数据和人工修改记录。
- AI 生成图片、视频、音频和 3D 按适用平台/地区要求执行标识、水印、披露和审核。
- 真人肖像、声音复刻、商标、音乐、字体和敏感行业进入专门审批。
- 数据主体访问、导出、更正、删除和法律保留形成可审计流程。
- 具体法规和平台政策由法务/合规建立版本化规则包，不在业务代码硬编码。

## 11. 前端质量基线

- 支持最近两个稳定版本的主流桌面浏览器；Browser RPA 控制台使用受控浏览器版本。
- 关键流程满足键盘操作、可见焦点、语义标签、颜色对比和错误可读性。
- 所有异步页面定义空、加载、排队、部分完成、失败、重试、无权限和离线恢复状态。
- 文案和时间/数字格式可国际化；MVP 默认简体中文，数据模型不锁死单语言。
- 高风险按钮明确描述动作、对象和影响，不使用模糊“继续”。

## 12. 工程验收

1. CI 能阻止破坏性 API/事件/数据库变更、Secret 和高危依赖进入主分支。
2. Staging 能完成四系统闭环、故障注入和回滚演练。
3. 跨租户、越权、Prompt 注入、恶意文件和重复外部写入通过安全测试。
4. 核心数据库和对象数据完成恢复演练并达到确认的 RPO/RTO。
5. 关键服务有 SLO、告警、Owner、Runbook 和 Kill Switch。
6. AI 生成资产带有来源、模型、权利和适用标识信息。
