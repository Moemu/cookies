## 1. 产品定义

本模块不是通用文件仓库，也不以“上传、文件夹、权限、去重”为主要价值。它围绕一个核心问题建设：**过去哪些素材在什么条件下有效或失效，下一次应该如何创作和投放？**

系统将素材内容拆解为可分析特征，与渠道、广告类型、受众、投放目标、预算、时间和效果数据关联，生成可追溯的素材洞察卡和经验库，再由 Codex/Skills 在需求、策略和创意环节按上下文复用。

## 2. 产品目标

1. 对小红书/公众号图文、电影感品牌广告，以及数字人、广告前贴、爆款复刻等效果广告进行不同维度的内容拆解。
2. 将素材特征与曝光、互动、转化、成本、品牌等数据关联，支持公平对比。
3. 识别有效模式、失败原因、适用条件、素材疲劳和异常变化。
4. 把一次性复盘沉淀为可检索、可确认、可引用、可失效的经验。
5. 向策略和创意提供具体建议，例如“优先测试什么钩子、避免什么组合”，而非泛化排行榜。
6. 保留事实、计算、推断和人工结论的边界，避免把相关性误写成因果。

### 非目标

- 不建设企业通用云盘或完整数字资产管理系统。
- 不以文件夹、复杂版权审批、外部分享和精细存储生命周期作为 MVP 核心。
- 不根据单一 CTR、CPA 或 ROAS 给素材做脱离上下文的全局排行。
- 不因某个素材历史表现好就保证下一次有效。
- 不自动删除、停用或替换真实投放素材。

### 素材分析内导航

进入一个 Asset/Analysis Project 后，导航为：`概览 → 内容拆解 → 效果趋势 → 对比组 → 实验 → 洞察 → 经验引用 → 数据与方法`。“数据与方法”必须展示数据截止时间、指标版本、Cohort 规则和 Skill/算法版本。

### 导航规则

- “分析素材库”只包含分析索引和版本引用，不扩张成网盘导航。
- 内容分析与效果分析是平级入口，支持从素材、数据和问题三种路径开始分析。
- 数据质量问题始终可从分析页面一键跳转，并保留原筛选条件。
- Provider、知识库和用户组织在 `/admin/*` 管理，本系统只管理特征体系、指标和分析 Skills。
- 权限使用 `insights.*` 动作，数据口径、经验确认和普通查看分别授权。

## 3. 用户与场景

| 角色 | 典型问题 | 期望输出 |
| --- | --- | --- |
| 策略人员 | “过去新品种草什么角度表现更好？” | 按人群/渠道/目标归纳的经验与反例 |
| 创意策划 | “数字人、广告前贴和爆款复刻应该分别测试什么？” | 按效果广告功能给出钩子、卖点、证明、CTA 和制作变量建议 |
| 品牌负责人 | “哪些品牌表达兼顾完播和品牌一致性？” | 品牌资产、叙事、情绪与指标的关联分析 |
| 投手 | “这批素材是不是开始衰退了？” | 疲劳趋势、异常证据、替换或观察建议 |
| 数据分析人员 | “这个结论是否受预算或受众影响？” | 分组对比、样本、混杂因素和口径说明 |
| 管理者 | “团队沉淀了哪些可复用方法？” | 经验库覆盖率、采纳率和业务影响 |

## 4. 分析对象与数据模型

| 对象 | 定义 |
| --- | --- |
| Asset | 被分析的图文、图片、视频、脚本或创意包，可保存文件或外部引用。 |
| AssetFeature | 从内容中提取的结构化特征，保留提取方式、版本和置信度。 |
| AssetContext | 渠道、广告类型、目标、受众、版位、预算、时间、策略和实验环境。 |
| AnalysisMetricSnapshot | 从投放指标来源构建的分析快照，保存粒度、窗口、口径、数据时间与新鲜度。 |
| AnalysisCohort | 为公平比较定义的一组素材及其筛选、基线和排除规则。 |
| AssetAnalysisRun | 一次分析任务的输入快照、方法、Skill 版本、结果和错误。 |
| InsightCard | 从数据与内容归纳的洞察，包含证据、适用条件、风险和反馈。 |
| ExperienceRule | 经人工确认并可被 Skills 引用的经验规则，支持版本、过期和反证。 |

素材可以只保存外部文件引用，但必须保留稳定标识、创意版本和平台对象关系，确保效果数据能正确归属。

## 5. 内容特征体系

### 5.1 小红书图文

- 标题：利益、问题、数字、反差、场景、身份、情绪、关键词。
- 正文：开场方式、内容结构、产品露出位置、体验/证明、CTA。
- 图组：封面构图、主体、文字密度、图片数量、叙事顺序、产品出现频率。
- 表达：生活化程度、品牌露出、商业感、语气、话题与搜索词。

### 5.2 公众号图文

- 标题与摘要：主题、承诺、信息密度和一致性。
- 文章结构：章节、篇幅、叙事/知识/案例类型、产品出现位置。
- 视觉：头图、内文图、引用和重点样式。
- 承接：CTA 类型、位置、链接、关注/私域/转化路径。

### 5.3 品牌广告

- 叙事：主题、冲突、情绪曲线、角色、场景和品牌角色。
- 品牌资产：Logo、品牌色、口号、声音、产品露出和记忆符号。
- 电影感：剧本结构、表演、镜头数、景别、机位、运镜、光线、色彩、声音、节奏和转场。
- 一致性：角色、产品、服装、道具、场景、光线和美术风格的跨镜头连续性。
- 渠道适配：开场、时长、画幅、封面和发布文案。

### 5.4 效果广告

- 钩子：问题、利益、结果、反差、猎奇、身份、场景和表现形式。
- 转化结构：痛点、卖点、机制、演示、证明、优惠、CTA。
- 制作特征：真人/数字人/商品、口播、字幕密度、镜头节奏和素材来源。
- 实验变量：受众、钩子、卖点、证明、CTA、人物、场景、时长。
- 数字人特征：数字人和声音、口型、表情、手势、语速、停顿、背景、商品层和 AI 标识。
- 广告前贴特征：目标时长、首帧、开场结构、单位时间信息量、静音可理解性、贴片和 CTA 出现时间。
- 爆款复刻特征：参考来源、结构映射、节奏相似度、原创改写程度、自有素材占比和版权风险。

自动特征必须标识为 AI 提取并保存置信级别；人工确认后成为可信特征。受控词表由管理员维护，避免同义词碎片化。

## 6. 数据指标体系

### 6.1 共同维度

- 渠道、账户、任务、创意、素材版本、广告类型。
- 目标、受众、版位、地域、时间、预算、出价和归因口径。
- 数据发生时间、同步时间、币种、时区和平台原始字段。

### 6.2 指标示例

| 内容类型 | 重点指标 |
| --- | --- |
| 小红书图文 | 曝光、阅读/点击、互动、收藏、评论、搜索/转化（视数据可用性） |
| 公众号图文 | 送达、打开、阅读完成、分享、关注、CTA 转化 |
| 品牌广告 | 播放、完播、互动、品牌搜索/调研指标、负反馈 |
| 效果广告 | 按数字人、广告前贴和爆款复刻分别统计消耗、曝光、点击、转化、CVR、CPA、ROAS、衰减速度 |

系统保存平台原始指标和统一指标字典。任何跨渠道对比必须展示口径差异，不能把名称相同但定义不同的指标直接合并。

## 7. 核心分析能力

### 7.1 单素材拆解

输出内容摘要、结构时间线/图文结构、关键特征、策略匹配、品牌/合规问题、效果趋势和可改进点。

### 7.2 素材对比

用户选择或由系统构建 AnalysisCohort，比较差异特征与结果。系统必须优先控制渠道、目标、受众、周期、预算和投放阶段，无法控制时明确列出混杂因素。

### 7.3 变体实验分析

当变体一次只改变一个主要变量且样本达到门槛时，分析该变量的相对表现；变量混杂或样本不足时只给方向性观察。

### 7.4 素材疲劳分析

识别随时间出现的曝光增大但点击/转化下降、频次上升、成本恶化等趋势，区分数据延迟、受众变化、预算变化和真正素材衰退。

### 7.5 模式归纳

从相似任务中归纳：

- 有效模式：什么内容元素在什么条件下表现相对更好。
- 失败模式：什么组合频繁低效或引发负反馈。
- 边界条件：行业、渠道、受众、目标、时间和样本范围。
- 下一步建议：保留什么、改变什么、优先测试什么。

### 7.6 经验失效

新数据与旧经验冲突时，系统生成反证提示。用户可将经验标记为待复审、已更新或已失效，不静默覆盖历史结论。

## 8. 洞察卡与经验库

### 8.1 洞察卡结构

- 结论：一句可执行描述。
- 类型：事实、统计观察、假设或建议。
- 适用范围：品牌、产品、渠道、广告类型、目标、受众和时间。
- 数据依据：素材数量、样本、时间窗口、指标和对比基线。
- 内容依据：关键素材特征与示例版本。
- 置信提示：充分、方向性、样本不足、存在混杂。
- 风险与反例：可能不适用的条件。
- 建议动作：用于策略、创意或投放的下一步。
- 状态：待确认、已确认、待复审、已失效。

### 8.2 经验引用

需求与策略助手、创意 Skills 只能默认引用“已确认且未失效”的经验。引用时必须带适用条件和来源链接，不能只把结论拼进 Prompt。

## 10. 关键交互

### 10.1 素材分析工作台

- 顶部：品牌、渠道、图文/视频、品牌/效果、效果广告功能、目标和时间筛选。
- 左侧：素材列表、Cohort、实验和待匹配数据。
- 中间：内容拆解、趋势、对比图和关键差异。
- 右侧：洞察卡、证据、适用范围、反馈和引用记录。

### 10.2 对话分析

用户可以提问：“最近两周快手数字人效果广告为什么成本上升？”Codex 先调用数据完整性、Cohort 和疲劳分析 Skills，再回答：

1. 可确认的事实。
2. 观察到的相关变化。
3. 不能排除的混杂因素。
4. 建议验证或行动。
5. 可点击的数据和素材证据。

### 10.3 防误读提示

- 样本不足、窗口过短或归因延迟时显著提示。
- 跨渠道或跨目标比较默认关闭，用户显式开启后展示口径差异。
- 数据异常时暂停生成强结论，先建议检查追踪、匹配和同步。

## 11. 状态与权限

### 11.1 分析状态

`待数据 → 待匹配 → 可分析 → 分析中 → 待确认 → 已确认/待复审/已失效`

### 11.2 权限

- 项目成员可查看本项目分析；跨项目经验根据品牌和组织权限脱敏展示。
- 数据分析人员可配置 Cohort 和指标口径，普通成员不能修改原始事实。
- 策略/创意人员可以提出洞察反馈，但确认组织经验需指定角色。
- 原始平台数据、客户名单和账户信息按最小权限访问。
- 经验删除采用逻辑删除，已被下游引用的历史版本仍可审计。

| `POST /api/insights/v1/assets/index` | 注册素材文件或外部引用及创意版本 |
| `POST /api/insights/v1/metrics/imports` | 导入效果数据并进行口径校验 |
| `POST /api/insights/v1/asset-mappings:resolve` | 处理平台对象与素材版本映射 |
| `POST /api/insights/v1/assets/{id}/features:extract` | 按内容类型提取特征 |
| `PATCH /api/insights/v1/assets/{id}/features` | 确认或修改内容特征 |
| `POST /api/insights/v1/cohorts` | 创建可复现的素材对比组 |
| `POST /api/insights/v1/analysis-runs` | 发起单素材、对比、实验或疲劳分析 |
| `GET /api/insights/v1/analysis-runs/{id}` | 获取方法、数据快照、结果和限制 |
| `POST /api/insights/v1/insights` | 从分析结果生成洞察卡 |
| `POST /api/insights/v1/insights/{id}/confirm` | 确认、编辑或驳回洞察 |
| `GET /api/insights/v1/experiences` | 按上下文检索已确认经验 |
| `POST /api/insights/v1/experiences/{id}/feedback` | 回传采纳、结果和反证 |

指标计算可重放；AnalysisRun 固化数据截止时间、查询条件、指标版本、Skill/算法版本和结果哈希。

## 13. 指标与埋点

- 可正确关联素材版本的效果数据比例。
- 四类素材的特征提取覆盖率、人工确认率和修改率。
- 分析任务成功率、P95 时长和数据新鲜度。
- 洞察确认率、驳回率、待复审率和平均确认时间。
- 经验被策略/创意引用、采纳、修改和拒绝的比例。
- 由经验驱动的创意占比及其相对基线表现。
- 被新数据反证或失效的经验比例。

关键事件：`asset_indexed`、`asset_metrics_imported`、`asset_mapping_resolved`、`asset_features_extracted`、`analysis_cohort_created`、`asset_analysis_completed`、`insight_generated`、`insight_confirmed`、`experience_reused`、`experience_challenged`、`experience_invalidated`。

## 14. 非功能要求

- 数据导入、特征提取和分析为异步任务，支持增量、幂等和断点恢复。
- 常规分析页面查询 P95 小于 1 秒；复杂计算展示进度和预计范围。
- 原始事实、计算结果、AI 推断和人工结论分别存储，不相互覆盖。
- 金额使用定点数和币种，时间保留平台时区与 UTC。
- 任何分析都能追溯到素材版本、数据快照、方法和 Skill/算法版本。
- 指标或特征体系变更后支持重算，不静默改写历史报告。
- 分析数据按组织隔离，模型输入只包含当前任务所需的最小数据。
- 平台授权、同步、Raw/Canonical 分层、对象映射、指标和归因遵循 [广告数据 Connector](./10-ad-data-connectors.md)。
- 素材二进制和预览统一使用 [媒体资产平台](./11-media-asset-platform.md) 的 Asset ID/Version。
- 页面状态、AI 结论披露和需求追踪遵循 [PRD 通用交互与质量要求](./15-prd-cross-cutting-requirements.md)。

## 15. MVP 验收标准

1. 系统能正确区分小红书图文、公众号图文、品牌广告，以及数字人、广告前贴和爆款复刻效果广告。
2. 每类素材使用专属特征体系，不把视频钩子字段套到公众号文章。
3. 投放数据能关联到具体 CreativeVersion；无法匹配的数据进入待处理队列。
4. 用户能分别查看数字人、广告前贴和爆款复刻的专属特征，以及钩子、卖点、证明、CTA 与 CPA/CVR 的对比。
5. 用户能查看品牌广告的故事、电影感、品牌资产、跨镜头一致性与完播或品牌指标的关联分析。
6. 小红书与公众号数据不会在没有口径说明时直接合并排行。
7. 变体改变多个主要变量时，系统提示无法归因到单一变量。
8. 疲劳分析能区分数据延迟、受众/预算变化和可能素材衰退。
9. 洞察卡包含结论、样本、适用条件、证据、风险和下一步建议。
10. 只有已确认、未失效经验能被需求/创意 Skills 默认引用。
11. 新数据与经验冲突时生成待复审提示，不静默覆盖原经验。
12. 任一分析结论能回溯到素材、数据截止时间、指标和 Skill 版本。
13. `/insights/*` 独立提供数据接入、内容/效果分析、实验、经验和数据质量导航，不出现通用网盘式业务菜单。

## 16. 依赖与风险

| 风险 | 缓解措施 |
| --- | --- |
| 素材与投放数据无法准确关联 | 稳定 CreativeVersion ID、平台映射、待匹配队列和人工修复 |
| 不同渠道指标不可比 | 保存原始口径、统一字典、默认限制跨渠道比较 |
| 小样本产生过强结论 | 样本门槛、置信提示、方向性表述和人工确认 |
| 投放变量混杂导致错误归因 | Cohort 控制、实验识别、列出混杂因素和建议补充实验 |
| AI 特征提取错误 | 置信级别、人工确认、受控词表和分类评测集 |
| 历史经验造成创意趋同 | 经验适用边界、反例、探索配额和失效机制 |
| 数据延迟诱发错误优化 | 数据新鲜度、归因健康检查和强结论暂停 |

## 17. 待确认项

1. 小红书、公众号、抖音、快手首期可获得的数据字段与授权方式。
2. 品牌广告的核心效果数据来自平台、品牌调研还是业务自有数据。
3. 效果广告实验的最低样本和观察周期由全局规则还是行业模板配置。
4. 谁拥有组织经验的最终确认与失效权限。
5. MVP 是否保存素材原文件；本稿允许只保存受控引用与分析所需预览。
