# Strategy → 创意任务策略：深度优化与真实可用性研究

日期：2026-07-30
范围：Strategy 服务、策略工作区前端、素材读取与任务策略生成；不修改 Creative 生产代码。

## 1. 最终产品判断

Strategy 与“创意任务策略”不是两套互相覆盖的策略：

- Strategy 是项目级事实与方向层，回答目标、受众、核心主张、渠道、约束、证据和衡量方式。
- 创意任务策略是某个具体创意业务的任务级派生层，回答这个业务应优先表达什么、还缺什么、验证哪些变量、素材可如何参与。
- Creative 是执行层，继续负责概念、文案、脚本、分镜、镜头、模型 Prompt、剪辑和最终版本。

任务策略必须引用不可变 `BriefVersion` 和可选的 `StrategyRevision`，只能补充业务增量信息，不能复制出第二份 Brief，也不能替 Creative 写执行答案。

## 2. 外部研究转成的设计准则

本次方案采用以下一手资料：

1. [Google PAIR：Mental Models](https://pair.withgoogle.com/guidebook-v2/chapter/mental-models/)
   用户需要知道系统能做什么、不能做什么。对应实现是：推荐只叫“策略适配”，素材明确区分“读过语义”“只核验规格”“不可用”。
2. [Google PAIR：Explainability + Trust](https://pair.withgoogle.com/guidebook-v2/chapter/explainability-trust/)
   解释应在决策发生时出现。对应实现是：在业务卡片之前展示准确的 Brief 版本、目标、渠道、交付、行业、素材状态和推荐政策版本。
3. [Google PAIR：Feedback + Control](https://pair.withgoogle.com/guidebook-v2/chapter/feedback-controls/)
   自动化不能夺走用户控制。对应实现是：推荐排序不等于权限；用户始终可选择非推荐业务，并看到不匹配原因。
4. [Google PAIR：Data Collection + Evaluation](https://pair.withgoogle.com/chapter/data-collection/)
   评估应覆盖代表性任务和失败模式。对应实现是：推荐规则用纯函数和 Golden Case 回归，专门覆盖饮料转化被误推游戏等假阳性。
5. [NIST AI RMF Generative AI Profile](https://www.nist.gov/publications/artificial-intelligence-risk-management-framework-generative-artificial-intelligence) 与 [NIST AI RMF Core](https://airc.nist.gov/airmf-resources/airmf/5-sec-core/)
   生成式系统要记录来源、限制、评估和风险处理。对应实现是：冻结 Brief、Profile、Skill、Prompt、策略版本和 Hash；权利、事实、素材分析状态不允许模型自行推断。
6. [Multimodal Recommender Systems Survey](https://arxiv.org/abs/2302.03883) 与 [Semantic Alignment in Multimodal Recommender Systems](https://arxiv.org/abs/2508.04571)
   图片或视频“存在”不等于它们的语义已被模型理解。对应实现是：只有存在 AssetFeature 分析记录时才允许把画面语义用于策略；否则媒体只用于格式、时长、画幅和生产准备。

## 3. 用户完整流程

```text
确认 Brief
→ 查看推荐使用的事实和素材状态
→ 查看按匹配度排序的业务
→ 接受推荐或自主选择其他业务
→ 只补充该业务相对 Brief 缺失的问题
→ 保存并重新校验
→ 生成任务策略
→ 查看业务专属判断、假设、证据、限制和素材用途
→ 导出 Markdown 给 Creative 人工开工
```

交互上的硬要求：

- 推荐卡必须真的按推荐名次排序，不能只显示名次标签。
- 推荐理由必须来自确定性规则，不能由模型临时编造。
- 不匹配的业务仍可选，但必须展示缺少的必要条件。
- 已生成计划刷新后必须恢复完整结果；历史推荐要按当前政策标出变化。
- 未保存答案不能发起生成；生成期间表单不可编辑。
- `asset_ref` 必须从当前 Project 的 ready 素材中选择，不能让用户手填跨项目 ID。
- 历史策略缺少新字段时不能白屏。

## 4. 推荐策略

推荐分两层：

### 4.1 资格门

用于避免高代价假阳性：

| 业务 | 自动推荐的必要事实 |
| --- | --- |
| 小红书图文 | 渠道包含小红书 |
| 公众号文章 | 渠道包含微信生态 |
| 短剧前贴 | 有明确短剧正片语境 |
| 游戏前贴 | 项目明确属于游戏业务 |
| 电商前贴 | 目标明确为转化或销售 |
| 爆款复刻 | 有类型明确的参考内容信号 |
| 品牌广告 | 目标明确为品牌认知或长期品牌资产 |

不满足资格门只退出自动推荐，不禁止用户手动选择。

### 4.2 匹配排序

在通过资格门的业务中，根据目标、渠道、交付、行业和素材信号做稳定排序。分数只用于同一政策版本内的相对顺序，不展示为成功概率。

推荐快照冻结：

- `policy_version`
- `brief_id`、`brief_version`、`brief_hash`
- 归一化后的信号
- 素材评估
- 推荐项与备选项
- Profile 版本和 Hash

## 5. 图片和视频到底有没有用

结论是“有用，但用途必须按证据分级”。

### 5.1 `semantic`

条件：当前 Project 中的精确素材版本为 ready，且有对应的 AssetFeature 分析记录。

允许：

- 使用已记录的画面、物体、场景、文本或节奏观察。
- 把这些观察转成信息优先级、假设或素材适配判断。

禁止：

- 超出分析记录推断未见内容。
- 把模型观察当成商品事实或权利证明。

### 5.2 `production_only`

条件：素材存在且 ready，但没有语义分析记录。

允许：

- 核验图片/视频类型、格式、分辨率和时长。
- 确认生产输入已经准备。
- 在页面提供图片预览和视频播放，帮助用户确认选对素材。

禁止：

- 声称看过画面、声音、文案或叙事内容。
- 用它作为业务推荐的语义依据。

### 5.3 `unavailable`

条件：素材不属于当前 Project、版本不存在、无权访问或未 ready。

处理：

- 不能保存为有效任务答案。
- 历史引用仍可展示，但进入开放问题，不能成为策略依据。

### 5.4 参考视频 URL

当前服务不自动下载、截帧或把外部 URL 送入模型。URL 可用于人工定位和抽象机制讨论，但不表示已取得复制、改编、音乐、肖像、商标或商业传播权。`rights_status=unknown` 不阻塞 Strategy 分析，进入生产使用前仍需按实际用途确认。

## 6. 任务策略深度标准

一份可用任务策略至少包含：

- 与 Brief 完全一致的目标、核心受众和核心主张。
- 有顺序的信息层级，而不是字段说明。
- 至少两个可验证假设，包含陈述、变量和指标。
- 当前业务的专属判断，例如电商前贴的信息顺序、开场机制和商品保真要求。
- 只来自 Brief 的事实与证据列表。
- 生产素材要求和当前素材的真实可用程度。
- 约束、权利状态和开放问题。
- Profile、Skill、Prompt、Brief、StrategyRevision 和 Plan 的可追溯血缘。

模型输出后由服务端重新冻结事实、权利、媒体评估和生产要求。空集合统一序列化为 `[]`，避免真实模型返回 `null` 造成契约失效或页面白屏。

## 7. 当前实现与依赖边界

现在可独立完成：

- Strategy 自持七类创意业务目录。
- 确定性推荐、解释和手动覆盖。
- 业务专属增量问题。
- Project 素材选择、版本校验和媒体评估。
- 异步真实模型生成、确定性降级、版本冻结。
- 页面查看、历史恢复和 Markdown 导出。

当前不依赖 Creative 改代码，但仍有明确边界：

- 目录不是 Creative 实时运行能力，不能承诺模型、额度或渲染资源此刻可用。
- 没有 AssetFeature 时不能做图片/视频内容级策略。
- 参考 URL 不自动抓取。
- 不自动创建 CreativeTask；目前通过页面和 Markdown 人工交接。
- 是否“足够让 Creative 开工”仍需用真实任务持续评审，而不是只看接口成功。

## 8. 验收矩阵

| 场景 | 预期 |
| --- | --- |
| 饮料 + 转化 + 小红书/抖音 | 电商前贴优先；小红书图文可推荐；游戏不推荐 |
| 用户选择当前不推荐的游戏前贴 | 允许创建；显示缺少游戏业务条件；按游戏业务追问 |
| Brief 没有素材 | 明确说明推荐没有使用素材语义 |
| 选择 ready 图片/视频但无 Feature | 可预览；显示“仅核验规格”；不声称读过画面 |
| 存在 Feature | 显示语义观察，并允许进入任务策略上下文 |
| 素材跨 Project 或未 ready | 保存失败，不进入生成 |
| 真实模型返回空数组为 `null` | 服务端归一化为 `[]`，页面正常展示“无” |
| 刷新已生成计划 | 恢复最新更新计划和完整策略 |
| 历史计划来自旧推荐政策 | 显示“历史推荐；当前政策未推荐” |
| 生成期间修改答案 | 输入禁用，避免生成上下文与页面状态分叉 |

## 9. 运营评估

上线后应持续看：

- Top 1 采用率与手动覆盖率。
- 按业务统计的推荐→选择、选择→生成成功率。
- 假阳性和假阴性案例。
- 各问题缺失率与重复询问率。
- 素材语义可用率、仅规格可用率和不可用率。
- 模型输出首次校验通过率。
- Creative 开工前仍需追问的问题数。

最后一项比“生成按钮成功率”更能判断服务是否真正有价值。
