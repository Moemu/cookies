# AI 原生广告多平台商品链接解析：外部条件与公开页边界

日期：2026-08-14
范围：淘宝/天猫、1688、小红书；目标是形成与当前抖音解析器相同层级的商品快照（商品 ID、标题、主图、价格、销量/热度、可用于需求分析的商品事实）。
证据要求：仅采用平台官方开放平台与官方协议/文档。

## 结论先行

1. **其他平台可以效仿抖音做“公开分享页解析”，但只能作为 fallback，不能承诺达到长期稳定、可商用的同等级能力。** 当前抖音成功的原因，是分享跳转后的 URL 恰好带有可解码的 `goods_detail`。这不是一个官方稳定接口；字段、编码、反爬与登录策略变化后仍可能失效。
2. **淘宝/天猫最容易先达到抖音同等级。** 官方 `taobao.item.detail.get` 可按商品 ID 获取 `item、price、sku、trade、feature、props` 等模块，接口标注“不需要授权”，但仍必须注册淘宝开放平台应用，获得 AppKey/AppSecret，按 TOP 规则签名并取得接口权限。月销量/评价量要另调 `taobao.item.dealinfo.get`，该接口明确“需要授权”，需商家 OAuth 后的 SessionKey。
3. **1688可以达到标题、图片、价格、商品属性这一层，但应以开放平台应用和商品类 API 权限为生产路径。** 是否需要 OAuth/access token 取决于最终获批的应用场景和具体接口；不能把公开详情 HTML 当作稳定契约。
4. **小红书不能通过现有官方文档对任意小红书分享链接做通用商品详情查询。** 官方商品接口属于专业号小程序/服务商交易组件，面向授权商家同步到小红书商品库的商品。要稳定读取该商家商品，需要专业号小程序、服务商/开发者身份、商家授权及调用凭证；任意笔记或任意商城分享链接仍只能做公开页 fallback 或要求用户补充素材。
5. **“核心卖点”不是任何平台都保证返回的标准事实字段。** 可从标题、属性、详情描述、商品图中抽取候选卖点，再由用户确认；不能把 AI 推导内容标记为“平台提取事实”。

## 为什么抖音“不提供 API 也能做”，其他平台却不能直接照搬

当前抖音链路利用的是页面导航过程中的公开数据载荷：

```text
分享文案 -> v.douyin.com 短链 -> haohuo 落地地址
                              -> URL 中 goods_detail
                              -> 解码 JSON
```

它能工作不代表它具备官方 API 的稳定性。其他平台可以复制的是**解析器架构**，而不是复制 `goods_detail` 这个数据来源：

```text
原始分享内容
  -> 平台识别
  -> 短链/落地页解析（fallback）
  -> 商品 ID 规范化
  -> 官方商品 API（已配置时优先）
  -> 字段归一化与来源标记
  -> 缺失字段由用户补充
```

淘宝 `e.tb.cn` 就说明了差异：服务器可能返回 HTTP 200 的 JavaScript 落地页，而不是 301/302；解析器必须受控读取 HTML 并提取目标 URL。即使链接识别成功，标题、主图、价格和销量也不应依赖页面结构长期不变。

## 平台实施建议

### 淘宝/天猫

生产方案：

1. 支持 `e.tb.cn`、`m.tb.cn`、`s.tb.cn` 和标准淘宝/天猫链接。
2. 对 HTTP 200 短链落地页做受控解析：限制响应体大小、超时、跳转次数，只接受淘宝/天猫目标域名。
3. 提取商品 ID 后优先调用 `taobao.item.detail.get`，请求 `item、price、skuBase、skuCore、trade、feature、props` 等所需模块。
4. 若产品一定要展示月销量，增加商家授权流程并调用 `taobao.item.dealinfo.get`；未授权时将销量标记为“不可获取”，不能伪造或用页面文案冒充官方值。
5. 商品详情接口标注“不需要授权”不等于“不需要外部条件”：请求仍要求 TOP 分配的 AppKey、签名、时间戳等公共参数。

最低外部条件：

- 淘宝开放平台开发者账号与已创建应用；
- AppKey、AppSecret；
- `taobao.item.detail.get` 的应用接口权限；
- 如需月销量：商家授权回调地址、OAuth 流程、SessionKey 安全存储与刷新/失效处理、`taobao.item.dealinfo.get` 权限。

### 1688

生产方案：

1. 先稳定解析 offer ID，公开页只承担“识别商品”和在 API 不可用时提供最少字段。
2. 注册 1688 开放平台应用，按实际产品定位选择商品管理、铺货分销或跨境电商等业务场景并申请商品 API。
3. 用最终获批接口返回的商品标题、主图、SKU/价格和属性构造快照；字段能力和是否需要 access token 以控制台对该 AppKey 展示的接口标签为准。
4. 销量不是当前可承诺的统一公开字段；没有获批且有明确口径的接口时，不进入广告事实字段。

最低外部条件：

- 1688 开放平台开发者/企业主体；
- 已创建并获批业务场景的应用；
- AppKey、AppSecret；
- 商品 API 权限；
- 若接口要求授权：1688 商家/采购账号 OAuth 与 access token 生命周期管理。

### 小红书

生产方案需要先区分两种输入：

- **授权商家自己的小程序商品**：可以通过小红书交易组件的商品查询能力获得其商品信息。
- **任意小红书笔记/商城分享链接**：官方文档没有通用商品详情读取接口，公开页解析只能作 best-effort；提取不到商品图、价格或事实卖点时必须提示用户上传/填写。

最低外部条件（授权商品路径）：

- 商家成为专业号并创建小程序；
- 开发者接入交易组件，或注册为服务商；
- 服务商 AppID/凭证；
- 商家在小红书 App 完成服务商授权；
- 授权小程序调用凭证及刷新机制；
- 商品已通过同步接口进入该小程序商品库并满足审核要求。

该路径不能用来读取其他未授权商家的任意分享商品。

## 公开页面 fallback 的技术边界

公开页解析可以保留，但必须满足以下约束：

1. 只处理用户主动粘贴的单条链接，不做批量爬取、搜索枚举或绕过登录/验证码。
2. 限定支持域名、跳转次数、请求超时、响应体大小和内容类型，防止 SSRF 与超大页面。
3. 只解析浏览器可公开访问且页面直接返回的数据，不伪造登录态、不调用私有接口、不绕过风控。
4. 页面字段必须标记来源与采集时间；识别成功后立即持久化规范化 URL、商品 ID、快照和获准使用的图片，避免流程反复抓取。
5. 公开页结构变动、403/429、登录墙、验证码或字段缺失时，不应无限重试；降级为“已识别商品，但平台未开放详情，请上传商品图并补充信息”。
6. 公开页面解析不能承诺 SLA；生产 SLA 只能建立在官方 API 与已授权数据上。
7. 图片进入广告生产前仍需确认用户/商家的使用授权；“网页公开可见”不等于“拥有广告再利用版权”。

## 推荐交付顺序

1. **淘宝/天猫 Phase 1**：补全 `e.tb.cn` HTML/JS 落地页解析，保证商品 ID 与分享标题识别。
2. **淘宝/天猫 Phase 2**：申请 AppKey/AppSecret 与商品详情权限，接入官方详情；销量单独作为需要商家 OAuth 的增强项。
3. **1688 Phase 1**：稳定 offer ID、分享标题和公开页降级；同步启动开放平台应用/场景申请。
4. **小红书 Phase 1**：继续作为链接/笔记识别器；商品事实不足时明确要求用户补全。
5. **小红书 Phase 2（仅有明确商家业务时）**：接专业号小程序交易组件与商家授权，不把它包装成任意分享链接解析能力。
