# cookies 媒体资产平台规格

| 属性 | 内容 |
| --- | --- |
| 定位 | 图文、图片、音频、视频、3D、文档和 Computer Use 证据的共享存储与处理基座 |
| 原则 | 共享物理资产能力，业务语义和版本归各垂直系统所有 |
| 文档版本 | v0.1 |
| 文档状态 | 草案 |

## 1. 边界

媒体资产平台拥有二进制对象、技术元数据、派生文件、访问控制和处理任务；不拥有“该创意是否批准”“该素材是否有效”等业务结论。

- CreativeVersion 拥有创意内容与业务版本。
- Insights AssetIndex 拥有分析索引、特征和洞察。
- Provider Job 拥有生成过程，成功产物必须转存为 Asset。
- Computer Use 拥有证据关联，截图二进制由资产平台保存。

## 2. 核心实体

- `Asset`：全局 ID、组织、媒体类型、状态、所有者系统和内容哈希。
- `AssetVersion`：不可变二进制版本、大小、MIME、尺寸/时长、对象存储位置。
- `AssetDerivative`：缩略图、预览、转码、封面、波形、字幕、代理文件和 3D 预览。
- `AssetRelation`：来源、变体、镜头、音轨、合成、引用和替代关系。
- `AssetRights`：来源、作者、授权范围、地区、渠道、期限、人物/音乐/字体证明。
- `AssetProcessingJob`：扫描、探测、转码、抽帧、字幕、打包和删除任务。
- `UploadSession`：分片、校验、过期和完成状态。

## 3. 生命周期

`uploading → scanning → processing → ready | quarantined | failed → archived → deletion_pending → deleted`

- 生成或上传内容在 `ready` 前不能进入正式交付。
- `quarantined` 资产只对有权限的安全/运营人员可见。
- 被不可变业务版本引用的资产不能立即物理删除；先撤销新访问并执行影响分析。
- 删除采用对象存储、数据库、CDN、缓存和派生文件的可审计工作流。

## 4. 上传与摄取

1. 服务端创建 UploadSession，校验组织配额、媒体类型和预计大小。
2. 客户端使用短期签名 URL 分片直传对象存储。
3. 完成时校验分片、总大小和 SHA-256，服务端不信任客户端 MIME。
4. 执行恶意文件扫描、媒体探测、解压炸弹和格式检查。
5. 建立不可变 AssetVersion，异步生成派生文件。
6. 返回稳定 Asset ID；业务系统建立自己的语义引用。

相同哈希可以复用物理对象，但不同组织和不同授权记录不能因此共享访问权限。

## 5. 媒体处理

| 类型 | 基础处理 |
| --- | --- |
| 图片 | 尺寸/色彩探测、缩略图、Web 预览、EXIF 清理、必要水印 |
| 视频 | Codec/时长/画幅探测、代理转码、封面/抽帧、音轨和字幕提取 |
| 音频 | Codec/时长/采样率、波形、预览和字幕时间轴关联 |
| 3D | 格式/纹理检查、包完整性、轻量预览和清单 |
| 文档 | 类型探测、病毒扫描、预览和知识摄取引用 |
| 截图 | 敏感信息遮盖、短留存、证据水印和受限原图 |

处理 Job 幂等且保留输入版本、处理器版本、参数、输出哈希和错误。原件不被转码任务覆盖。

## 6. 生成资产接入

- Provider Job 只保存厂商任务 ID 和临时结果引用。
- 成功后由资产平台下载、校验、扫描、计算哈希并转存受控对象存储。
- 厂商临时 URL 不进入 CreativePackage 或长期业务引用。
- 记录逻辑模型、实际模型版本、Prompt/参数引用、种子、来源素材和生成时间。
- 部分生成结果分别建 Asset，失败项可单独重试。

## 7. 权利与合规元数据

资产交付前至少检查：

- 来源：上传、拍摄、购买、第三方、AI 生成或平台素材。
- 商用范围、渠道、地域、期限、是否允许改编和再生成。
- 人物肖像、声音、字体、音乐、商标和数据来源证明。
- AI 生成标识/水印要求及平台披露状态。
- 权利到期后的阻断、通知和历史投放影响。

未知授权默认为不可正式交付，而不是自动视为可用。

## 8. 访问与分发

- 所有访问先校验组织、项目、系统、资源权限和资产状态。
- 下载/预览使用短时签名 URL，默认禁止公开永久 URL。
- CDN 缓存键包含资产版本，不让新版本覆盖历史引用。
- 高敏原件、Computer Use 原截图和授权证明采用独立权限与访问水印。
- 导出包生成一次性下载并记录接收人、内容、版本和过期时间。

## 9. API

- `POST /platform/v1/assets/upload-sessions`、`:complete`、`:abort`。
- `GET /platform/v1/assets/{id}`、`/versions/{version}`、`/derivatives`。
- `POST /platform/v1/assets/{id}/processing-jobs`。
- `POST /platform/v1/assets/{id}/relations`。
- `GET/PATCH /platform/v1/assets/{id}/rights`。
- `POST /platform/v1/assets/{id}:archive|request-deletion`。
- `POST /platform/v1/assets/{id}/download-tokens`。

业务系统不能直接保存对象存储 Bucket/Key 作为公开契约，只保存 Asset ID 和版本。

## 10. 配额、成本与可观测性

- 按组织、项目、系统、媒体类型统计原件、派生文件、传输和处理成本。
- 配额覆盖总存储、单文件、每日上传、处理并发和导出大小。
- 指标覆盖上传成功率、扫描/处理时延、转码失败、签名 URL 错误、孤儿对象和删除积压。
- 定期对账数据库、对象存储、CDN 与业务引用，孤儿对象进入修复/回收队列。

## 11. 备份与删除

- 元数据数据库按平台 RPO/RTO 备份；对象存储启用版本与生命周期策略。
- 误删恢复窗口、法律保留和用户删除 SLA 按组织策略配置。
- 删除前计算 Creative、Insights、Delivery、Knowledge 和 Audit 引用。
- 历史审计可以保留不可还原的哈希与元数据，但不继续暴露已删除内容。

## 12. MVP 验收

1. 图片、视频、音频和文档可分片上传、扫描、探测并获得稳定 Asset ID。
2. 视频可生成预览、封面和基础元数据，原件不被覆盖。
3. Provider 临时结果能转存并追溯模型与来源素材。
4. Creative、Insights 和 Delivery 通过同一 Asset ID/Version 引用内容。
5. 未知或过期授权能阻断正式交付。
6. 跨组织无法通过哈希、URL 或缓存访问资产。
7. 删除能识别下游依赖并完成对象、派生文件和缓存对账。
