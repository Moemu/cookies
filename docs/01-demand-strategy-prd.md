## 1. 产品定义

本模块是 cookies 的默认入口。用户不需要先理解广告术语或填写长表单，只需像与广告策略顾问沟通一样描述目标。Codex 负责理解上下文、规划下一步并调用合适的广告 Skills；Skills 负责需求采集、品牌知识、受众洞察、策略规划、合规检查和产物生成。

对话是主交互，结构化 Brief 和策略是对话逐步形成的可编辑产物，而不是独立表单流程。

## 2. 产品目标

1. 用户通过自然对话在 15 分钟内形成一份可执行 Brief。
2. Codex 能根据对话阶段选择正确 Skill，不要求用户手工编排工具。
3. 对缺失、冲突和低置信信息进行自然追问，不重复询问已确认内容。
4. 将对话中的事实、假设、建议和待确认项持续沉淀为结构化产物。
5. 输出能直接驱动图文/视频创作和智能投放的策略版本。
6. 每次 Skill 调用、资料来源、人工修改和最终确认均可追溯。

### 非目标

- 不以多步骤表单作为主流程；结构化面板只用于查看、纠错和确认。
- 不把 Codex 的上下文当作长期数据库，业务事实由 cookies 后端保存。
- 不让模型替用户决定未经确认的预算、业务承诺或合规事实。
- 不在此模块执行真实投放。
- 不要求一个通用 Prompt 覆盖全部行业和渠道，专业流程由 Skills 扩展。

## 系统边界与模块导航

完整的 L0 至 L3 导航分布、路由与交互规则见 [四大模块导航与信息架构](./19-module-navigation-architecture.md)；子板块功能、必要性、价值和展示形式见 [四大模块子板块分析](./20-module-submodule-analysis.md)。本 PRD 维护业务职责。

### 系统边界

需求与策略是独立垂直系统，路由前缀为 `/strategy/*`。它拥有需求对话、Brief、研究产物、策略、实验方案和评审记录；只通过 [共享基座](./05-shared-foundation.md) 使用用户组织、Provider、知识库、Codex/Skills、任务、审批和审计。

| 类型 | 内容 |
| --- | --- |
| 本系统拥有 | Conversation、Brief、ResearchArtifact、Strategy、StrategyExperiment、StrategyReview |
| 从基座读取 | 用户/组织、品牌与项目知识、Provider、SkillDefinition、AgentTask、Approval |
| 从其他系统消费 | `insight.confirmed.v1` 素材经验事件和授权查询 API |
| 向其他系统发布 | `strategy.approved.v1`、`strategy.superseded.v1` |
| 明确不拥有 | Creative、AssetInsight、DeliveryPlan、PlatformEntity |

### Project 关联

- Project 是四系统共同的全局上下文，由共享基座拥有；本系统不再创建另一类“项目”。
- StrategyWorkspace、Conversation、Brief、ResearchArtifact、Strategy、StrategyExperiment 和 StrategyReview 必须携带非空 `project_id`。
- 一个 Project 默认创建一个主策略工作区；按市场、产品或阶段拆分时可创建多个，但工作区只属于一个 Project。
- 策略批准后只允许默认交接到同一 Project 的创意或投放对象；跨 Project 复用使用复制/引用动作并保存来源 Project 与版本。

### 策略工作区内导航

进入一个 StrategyWorkspace 后，二级导航固定为：`概览 → 对话 → Brief → 研究 → 策略 → 实验 → 评审 → 变更记录`。工作区内切换不跳转到创意、素材或投放页面；跨系统交接通过“发送到创意”“创建投放草稿”等明确动作完成。

### 导航规则

- 左侧栏由需求与策略系统独立维护，全局壳层只保留系统切换器。
- 一级导航记住用户最后访问的二级页面；工作区内记住最后打开的产物版本。
- 未启用研究或实验能力时隐藏对应入口，不显示空壳页面。
- 导航权限按 `strategy.*` 动作计算，不复用其他系统业务角色。
- 全局 Provider、知识库和用户管理通过 `/admin/*` 打开，不复制到本系统设置。

## 3. 用户与核心场景

| 角色 | 对话示例 | 期望结果 |
| --- | --- | --- |
| 市场负责人 | “下个月推新品，预算 30 万，想做小红书和抖音。” | 助手补齐目标、人群、卖点、排期和衡量方式 |
| 中小企业经营者 | “我不知道怎么投，只想多获得一些客户。” | 助手用非专业语言澄清业务和转化目标 |
| 策略人员 | “读一下这些品牌资料，按上次复盘生成新方案。” | 助手调用资料解析和历史经验 Skills，标明来源 |
| 项目负责人 | “把已确认需求生成一版品牌广告和效果广告策略。” | 形成电影感品牌故事，以及数字人、前贴或爆款复刻等效果广告策略 |
| 创意人员 | “为什么推荐这个钩子？” | 助手引用受众洞察、素材经验和策略依据 |

## 4. 对话助手架构

### 4.1 角色分工

| 组件 | 职责 | 不负责 |
| --- | --- | --- |
| cookies React 工作台 | 对话、Skill 运行卡、Brief/策略侧栏、版本确认、审批 | 不直接执行广告推理 |
| cookies Go 控制面 | 会话、权限、上下文组装、任务状态、产物落库、审计 | 不把领域逻辑硬编码进单一 Prompt |
| Codex | 理解意图、规划步骤、选择 Skill、调用工具、整合回答 | 不保存唯一业务事实，不绕过权限 |
| Skills | 封装广告工作流、规则、参考、脚本和结构化输出 | 不自行获得超出会话授权的工具 |
| 外部工具/数据源 | 文件解析、研究、数据查询、内容生成等原子能力 | 不决定最终策略和审批结果 |

### 4.2 MVP Skills 清单

| Skill | 触发场景 | 核心输入 | 主要输出 |
| --- | --- | --- | --- |
| `brief-intake` | 创建或补充广告需求 | 用户消息、当前 Brief | 字段更新、缺失项、下一轮问题 |
| `brand-context` | 需要品牌事实或规范 | 品牌 ID、任务范围 | 定位、语气、必说信息、禁用项 |
| `audience-insight` | 需要拆解目标人群 | 产品、目标、历史数据 | 人群分层、痛点、触发场景、假设 |
| `channel-strategy` | 确定内容与渠道打法 | Brief、目标渠道 | 小红书/公众号/抖音/快手策略 |
| `asset-experience` | 需要引用历史素材经验 | 品牌、渠道、广告类型 | 可复用经验、失败模式、适用条件 |
| `strategy-planner` | Brief 完整后生成方案 | 已确认 Brief、相关洞察 | 结构化策略、实验框架、衡量方案 |
| `compliance-review` | 确认需求或提交策略前 | 行业、地区、内容主张 | 阻断项、警告、所需证明 |
| `brief-strategy-export` | 需要评审或交付 | 指定版本 | Markdown/PDF/下游结构化产物 |

Skills 采用版本化发布。每次运行保存 Skill 名称、版本、输入摘要、输出、耗时、使用工具和结果；升级需通过固定评测集并支持回滚。

## 5. 核心对话流程

1. 用户创建或选中全局 Project，并创建策略工作区或直接发送第一条需求。
2. Go 控制面组装用户有权访问的品牌、历史任务和当前 Brief 摘要。
3. Codex 判断当前意图与阶段，调用 `brief-intake`，必要时组合其他 Skills。
4. 助手用自然语言总结已理解内容，每轮最多追问 1—3 个高影响问题。
5. 结构化 Brief 侧栏实时更新，新增和冲突字段高亮，用户可以直接纠正。
6. 达到完整度门槛后，助手主动提出“确认 Brief”并展示阻断项与假设。
7. Brief 确认后，Codex 调用 `strategy-planner`，按渠道和广告形态生成策略。
8. 用户继续用对话修改指定章节；助手说明修改会影响的下游内容。
9. 策略批准后生成不可变版本，交给创意和智能投放模块。

## 6. 对话体验要求

### 6.1 助手回复结构

一次典型回复由以下元素按需组成：

- 对用户意图的简短确认。
- 已更新的信息摘要。
- 本轮调用的 Skill 及运行状态。
- 需要用户回答的 1—3 个问题。
- Brief/策略产物卡片及“查看变更”入口。
- 明确的下一步动作，例如确认 Brief、生成策略或创建创意任务。

用户不需要看到模型内部推理。界面只展示对业务有用的步骤、工具状态、依据、错误和产物。

### 6.2 追问规则

- 先问影响业务目标、受众、渠道、预算或合规的高优先级缺口。
- 问题使用业务语言，并提供“由助手建议”“暂不确定”等低门槛选项。
- 不重复询问已由用户确认的事实；如资料冲突，引用冲突来源让用户选择。
- 用户连续跳过时停止追问，将该项写为假设或投放前阻断项。
- 用户切换话题时保存当前阶段，完成临时问题后可继续原流程。

### 6.3 Skill 运行卡

运行卡展示 Skill 名称、目的、状态、读取的数据范围、产物和错误恢复。涉及外部研究、敏感资料或写操作时，按权限策略先请求授权。

状态：`待运行 → 运行中 → 等待用户 → 已完成 → 部分完成/失败/已取消`。

### 6.4 暂停与恢复

- 页面刷新或用户稍后返回时，从后端保存的会话阶段和产物恢复。
- 长任务完成后以消息和产物卡追加到原会话，不伪造为即时回复。
- Skill 失败时保留之前成功结果，允许只重试失败步骤。
- 会话过长时由系统生成可审计摘要；关键业务事实仍从结构化数据读取。

## 7. Brief 数据规范

| 分组 | 关键字段 | 确认要求 |
| --- | --- | --- |
| 基本信息 | 品牌、产品、行业、地区、语言 | 必填 |
| 业务目标 | 推广目标、优先级、期望业务结果 | 第一目标必填 |
| 受众 | 核心人群、痛点、场景、地域、排除人群 | 核心人群和地域必填 |
| 产品价值 | 卖点、证据、价格/优惠、竞品差异 | 至少一个有依据的卖点 |
| 内容与渠道 | 小红书、公众号、抖音、快手；图文/视频；品牌/效果；效果广告功能 | 至少确认一个组合 |
| 预算与排期 | 总/日预算、币种、时间、节奏 | 进入投放前必填 |
| 转化与指标 | 转化事件、CPA/ROAS/CVR 或品牌指标 | 至少一个主指标 |
| 创意要求 | 语气、必说、禁用、视觉、时长/篇幅 | 可继承品牌规范 |
| 合规 | 行业限制、声明、版权/肖像、数据约束 | 敏感行业必填 |
| 参考资料 | 历史广告、竞品、研究、会议材料 | 选填 |

AI 抽取字段保存来源、置信级别、确认状态和修改人。用户确认值高于模型推断；任务级值可以覆盖品牌默认值，但必须展示覆盖关系。

## 8. 策略输出规范

1. 执行摘要：目标、关键判断、机会和风险。
2. 受众策略：人群、需求、触发场景、反对理由和优先级。
3. 价值与信息架构：主张、证据、主信息、辅助信息和 CTA。
4. 渠道策略：小红书、公众号、抖音、快手的角色与内容适配。
5. 创意策略：图文方向；电影感品牌故事方向；数字人、广告前贴和爆款视频复刻等效果广告方向。
6. 预算与节奏建议：区间、假设、探索/放量比例和保护条件。
7. 实验矩阵：变量、对照、周期、样本提示、胜出与停止条件。
8. 衡量方案：指标、事件、数据源、归因口径和复盘节奏。
9. 假设与缺口：未验证内容、影响和验证动作。
10. Skill 依据：使用的品牌知识、素材经验、研究来源和 Skill 版本。

## 10. 状态与权限

### 10.1 会话状态

`进行中 → 等待用户 → 生成中 → 待确认 → 已完成/已取消`

会话完成不等于产物已批准。Brief 与策略分别保留草稿、待评审、已确认/已批准、已替代状态。

### 10.2 权限

- 项目成员可对话和编辑草稿，只读成员只能查看。
- Codex 只能收到当前用户与当前任务获准的数据和工具。
- Brief 确认、策略批准和敏感 Skill 调用使用独立权限。
- Skill 的安装、发布、禁用和外部依赖配置由管理员负责。
- 已被下游引用的版本不可修改或物理删除。

消息发送、确认和生成操作使用幂等键。Codex/Skill 事件携带 `conversation_id`、`task_run_id`、`skill_run_id` 和单调递增序号，支持重连去重。

## 12. 指标与埋点

- 首次对话到 Brief 确认的转化率和中位时长。
- 平均对话轮数、追问回答率、重复问题率和用户中断点。
- Skill 选择准确率、成功率、P95 时延、重试率和单任务成本。
- Brief 字段抽取确认率、冲突发现率和人工修改率。
- 策略采纳率、章节修改距离、退回率和批准时长。
- 因上游理解错误导致的创意/投放返工率。

关键事件：`conversation_created`、`message_sent`、`skill_selected`、`skill_run_completed`、`assistant_waiting_user`、`brief_updated`、`brief_confirmed`、`strategy_generated`、`strategy_approved`、`conversation_resumed`。

## 13. 非功能要求

- 用户消息提交后 1 秒内显示已接收状态，首个可见进度目标小于 3 秒。
- 长任务可暂停、恢复、取消和逐步骤重试；页面关闭不丢失结果。
- 结构化 Skill 输出必须通过 Schema 校验，失败不可写入有效 Brief/策略。
- 会话摘要不能覆盖用户确认事实；所有关键事实从后端结构化存储读取。
- Skill 和工具调用遵守超时、并发、配额、权限和数据留存策略。
- 不向模型发送无关项目、完整账户凭据或超出任务范围的客户数据。
- Codex Agent Task、Skill 包、上下文、隔离和恢复遵循 [Codex 与 Skills 运行时](./09-codex-skills-runtime.md)。
- 页面状态、并发编辑、AI 披露和需求追踪遵循 [PRD 通用交互与质量要求](./15-prd-cross-cutting-requirements.md)。

## 14. MVP 验收标准

1. 用户用一段自然语言发起需求后，助手能调用 `brief-intake` 并生成带来源的 Brief 草稿。
2. 用户无需切换到表单即可完成主要需求收集；侧栏修改能同步回对话上下文。
3. 缺少目标人群和转化事件时，助手优先追问且不重复询问已确认信息。
4. 资料中出现两个预算时，助手展示冲突来源，未经确认不自动采用。
5. 助手能针对“小红书图文 + 抖音效果广告”调用不同渠道和效果广告功能策略能力。
6. 每个 Skill 运行可查看版本、目的、状态、输入范围和产物。
7. Skill 部分失败时保留成功结果，只重试失败步骤。
8. Brief 有阻断项时不能确认；确认后形成不可变版本。
9. 用户用对话修改策略受众后，系统展示受影响章节并创建新版本。
10. 已批准策略可被创意模块读取，并追溯到 Brief、会话和 SkillRun。
11. 页面刷新后可恢复会话、待回答问题和已完成产物。
12. 未授权用户不能调用读取其他项目数据的 Skill 或批准策略。
13. `/strategy/*` 可独立加载完整导航和策略工作区内导航，不依赖创意、素材或投放系统页面可用。

## 15. 依赖与风险

| 风险 | 缓解措施 |
| --- | --- |
| 对话发散、迟迟无法形成产物 | 阶段状态机、每轮明确下一步、结构化 Brief 侧栏 |
| Codex 选错 Skill | 清晰 Skill 描述、允许工具白名单、路由评测和用户可见纠正 |
| Skill 数量增长导致冲突 | 分领域命名、触发边界、版本注册、冲突测试和管理员发布 |
| 长对话导致事实漂移 | 后端事实存储、可审计摘要、每次运行重新读取有效版本 |
| 工具读取过多敏感数据 | 最小上下文、项目权限、调用前授权和输出脱敏 |
| 外部研究或模型结论无依据 | 强制来源/假设标记，无法验证时不作为事实 |

## 16. 待确认项

1. 生产采用受控远程 Worker；仍需确认开发环境本地 Worker 的网络、数据和工具白名单。
2. 首期 Skills 的负责人、发布审核和回滚机制。
3. MVP 附件格式、单文件限制和数据留存周期。
4. 哪些外部研究能力允许自动调用，哪些必须先获用户许可。
5. 企业级自定义 Skills 是否进入 M1；本稿默认在 P1。

## 17. 设计依据

Codex Skills 用于封装可复用工作流、规则、参考与脚本，并支持显式或按任务描述隐式触发；本 PRD 据此将广告专业方法从通用对话 Prompt 中拆出。参见 [OpenAI：Build skills](https://learn.chatgpt.com/docs/build-skills)。
