# Strategy × Creative 需求对齐指南

| 属性 | 内容 |
| --- | --- |
| 目标 | 帮助 Strategy 先完成内部需求梳理，再与 Creative 对齐能力、边界、交接方式和首期范围 |
| 适用对象 | Strategy 产品、Creative 产品、研发、设计、运营及审核人员 |
| 推荐方式 | 先完成一页纸准备，再召开一次 60 分钟对齐会 |
| 首期原则 | 先跑通一个真实创作任务，再复制到其他能力 |

## 1. 对齐目标

Creative 最近开放了较多新能力。Strategy 需要知道：

- Creative 当前真正能做什么。
- 每项能力适合什么业务场景。
- 创建任务前必须提供什么信息和素材。
- 缺少什么条件时可以继续规划，缺少什么条件时必须停止生成。
- Strategy 应该推荐什么创作路线。
- Creative 结果如何回到 Strategy，验证原来的假设。

本次对齐不是让 Strategy 介入脚本、分镜、Prompt 或剪辑，而是建立一套稳定的协作方式：

```text
Strategy 明确目标和约束
→ 推荐创作路线
→ Creative 完成具体创作和生产
→ 结果回流验证 Strategy 假设
```

## 2. Strategy 会前自我对齐

### 2.1 为什么要做这次对齐

建议统一表述：

> Creative 新增能力后，Strategy 应能够判断哪些场景适用、需要什么输入以及要验证什么假设，避免推荐的路线无法执行，也避免 Creative 产出无法回到 Strategy 复盘。

### 2.2 Strategy 要解决的问题

Strategy 负责：

- 判断当前项目适合哪些创作任务。
- 明确业务目标和成功指标。
- 明确目标受众及其需求、痛点或张力。
- 提供核心主张、信息优先级和可信证据。
- 提供品牌、事实、渠道、版权和合规限制。
- 推荐可选创作路线并解释原因。
- 提出需要验证的变量、假设和观察指标。

### 2.3 Strategy 明确不做的事情

Strategy 不负责：

- 最终 Hook 文案。
- 完整脚本和分镜。
- 镜头、运镜、转场和视觉表现。
- 最终 Prompt。
- 模型、模板和供应商参数。
- 剪辑时间线和具体制作步骤。
- 生成失败后的技术重试方式。
- 替 Creative 判断产物是否达到制作标准。

### 2.4 首期范围

不要一次性对齐所有 Creative 功能。

建议先选择一个后端、前端和生产流程已经比较成熟的任务，例如：

> 使用“电商前贴”跑通一次 Strategy → Creative → 效果回流闭环。

跑通后，再复制到：

- 短剧前贴。
- 爆款复刻。
- AI 混剪。
- 品牌视频。
- 数字人广告。
- AI 广告生成。

### 2.5 首期成功标准

- Strategy 能推荐一条创作路线并解释原因。
- Creative 能直接使用 Strategy 提供的信息开始规划。
- 信息不足时，Creative 能明确指出需要 Strategy 补充什么。
- Creative 任务能追溯到具体 Strategy 版本和实验假设。
- 创意版本和最终素材可以被效果数据准确关联。
- 结果能够判断原 Strategy 假设是得到支持、未得到支持，还是证据不足。

## 3. Strategy 与 Creative 的职责边界

### 3.1 三层分工

```text
核心 Strategy
目标、受众、主张、证据、品牌与合规限制
        ↓
任务 Strategy 说明
为什么选择这种创作方式、重点验证什么、必须具备什么
        ↓
Creative 执行方案
Concept、Hook、脚本、分镜、Prompt、生成、剪辑和候选评审
```

前两层由 Strategy 负责，最后一层由 Creative 负责。

### 3.2 任务级分工示例

| 创作任务 | Strategy 需要提供 | Creative 负责决定 |
| --- | --- | --- |
| 电商前贴 | 核心卖点、目标受众、正片承接关系、实验变量、事实和品牌限制 | 开场动作、画面、镜头、Prompt、前贴生成与拼接 |
| 短剧前贴 | 剧情衔接、目标情绪、可用冲突、角色与世界观限制 | Hook、对白、分镜、表演、视频生成和剪辑 |
| 爆款复刻 | 参考原因、允许借鉴的机制、禁止复制内容、目标商品映射、实验目标 | 结构拆解、原创改写、Prompt、候选生成和相似性检查 |
| AI 混剪 | 前中后段传播任务、素材优先级、主张、CTA 和变量设计 | 选片、Shot、时间线、节奏、包装、渲染和质检 |
| 数字人广告 | 数字人角色定位、受众、口播任务、证据、授权和行业限制 | 台词、语速、表演、场景、口型、字幕和成片 |
| 品牌视频 | 品牌心智、目标情绪、文化语境、核心记忆点和品牌边界 | 故事、人物、场景、剧本、视听语言和制作 |
| 小红书图文 | 种草或搜索目标、决策障碍、内容角度、证据和互动意图 | 标题、正文、封面、图组、排版和发布建议 |

### 3.3 什么时候需要更新 Strategy

以下变化需要发布新的 Strategy 版本：

- 目标发生变化。
- 目标受众发生变化。
- 核心主张或主要卖点发生变化。
- 商品、活动机制或事实声明发生变化。
- 实验假设或主要变量发生变化。
- 从品牌传播变成效果转化，或反向变化。
- 切换渠道后，原 Strategy 的适用条件不再成立。

以下变化通常不需要更新 Strategy：

- 调整脚本措辞。
- 更换镜头或视觉风格。
- 修改 Prompt。
- 更换生成模型。
- 调整剪辑节奏。
- 在同一 Strategy 路线内生成更多候选。

## 4. Creative 能力盘点

会议前由 Creative 填写或确认下表。

### 4.1 当前代码能力判断

以下结论基于 2026-07-30 仓库代码、OpenAPI、服务装配方式和领域测试，不以 PRD 或页面是否出现为唯一判断依据。

#### 现在可以直接开展，不需要修改 Creative 代码

| 工作 | 当前可做程度 | 使用边界 |
| --- | --- | --- |
| 对齐双方职责和首期任务 | 可以直接做 | 属于产品与流程工作，不依赖研发 |
| 盘点 Creative 能力成熟度 | 可以直接做 | 需要 Creative 对正式、Beta、实验和规划状态进行业务确认 |
| 使用现有 Strategy 字段描述任务策略 | 可以直接做 | 可使用 `creative_recommendations`、`platform_plans`、`experiment_matrix`、`measurement` 和 constraints |
| 使用已确认 Brief 或已批准 StrategyPackage准备电商前贴 | 已有正式读取与准备接口 | 可以读取不可变来源、产品事实和素材，并计算 generation readiness |
| 电商前贴生成并进入素材库 | 条件满足时可以 | 需要已配置真实 Provider、合格商品素材和 generation gate 通过 |
| 小红书图文 Intake、任务、逐图生成、冻结、检查、批准和交付 | 已有领域闭环 | Strategy 来源会被归一化为 CreativeIntake；当前映射仍包含部分默认值 |
| 通用五秒前贴的 StrategyPackage → CreativeIntake → VideoTask | 旧链路可以使用 | 只支持抖音/快手、`pre_roll`、5 秒、9:16，不等于新的细分能力路由 |
| 手工创建短剧前贴任务 | 可以 | 目前依赖 Creative 手工 Intake，不会自动消费 Strategy 的任务级路线 |
| 手工创建爆款复刻任务 | 可以 | 可以分析参考视频、编辑五维 Prompt、确认权利、生成候选和送审，但 Strategy 信息需要手工带入 |

#### 可以演示或局部使用，但不能视为正式 Strategy × Creative 闭环

| 能力 | 已有部分 | 当前限制 |
| --- | --- | --- |
| 游戏前贴 | 页面、确认 Brief 和通用视频生成调用 | 没有完整的专属 CreativeTask、不可变输入、候选、审核和交付链路 |
| AI 混剪 | Plan、RenderJob、QualityReport、HitAnalysis、ProductMapping、反馈和评测 API | 当前主服务装配使用内存存储、No-op RenderScheduler 和 FakeQualityEvaluator；服务重启后数据不可作为正式业务事实 |
| Remix 反馈和权重快照 | append-only feedback、聚合和权重计算 | 当前为内存存储，且没有关联 Strategy hypothesis、CreativeVersion、投放单元和指标观察窗 |
| 新版 Strategy Creative Handoff | v1 Schema、Hash、冻结读取和多 Route 结构 | Strategy 实际 Route 生成主要只有小红书图文；旧 `pre_roll` 会在新版 Handoff 中被标记为 mode 不完整 |
| 品牌视频 | 数据契约和 Fixture 中已有 mode | 没有完整的品牌视频创作、制作和交付闭环 |

#### 必须修改 Creative 或双方代码，目前不能正式实现

| 需求 | 为什么现在不能做 | 主要改动方 |
| --- | --- | --- |
| Strategy 自动发现 Creative 新能力 | 当前没有 Creative 业务能力目录和 effective capability API | Creative |
| Strategy 自动判断某个 Project 可用、缺条件或不可用 | 当前没有项目级能力解析器，只能依赖静态枚举和页面判断 | Creative 为主，Strategy 接入 |
| 短剧前贴、爆款复刻、游戏前贴、AI 混剪由 Strategy Route 自动创建 | 当前正式 StrategyPackage 只产生通用 `pre_roll`，细分任务主要依赖手工入口 | Strategy + Creative |
| 用 `capability_ref` 冻结能力版本 | 当前 Handoff 和 Intake 没有统一业务能力引用 | Strategy + Creative |
| 新能力上线后 Strategy 不改枚举即可使用 | 当前 Handoff Schema、Strategy Route 和 Creative Intake 各自维护 mode 集合 | Strategy + Creative |
| 能力暂停后保留历史任务、阻断新生成 | 当前没有不可变能力版本与动态 availability 的分离 | Creative |
| Strategy 缺失信息时不再由 Creative 自动补默认 CTA、Concept 或视觉关键词 | 当前 StrategyPackage 到 Intake 的适配代码仍会写入默认值 | Creative 为主，Strategy补结构化输入 |
| AI 混剪作为正式生产能力 | 需要持久化 Store、真实 RenderScheduler、真实 QualityEvaluator、成片入库和恢复机制 | Creative / Platform |
| Creative 结果自动回流 Strategy hypothesis | 当前缺少统一关联键、持久化反馈、领域事件和人工确认经验流程 | Creative + Insights + Strategy |
| 数字人广告 | 当前主要存在于 PRD，没有正式任务和生产链路 | Creative |
| AI 广告生成 | 当前主要存在于 PRD，没有端到端生成、评审和交付闭环 | Creative |
| 公众号图文 | 当前没有与小红书图文同等级的独立内容 Schema 和任务闭环 | Creative |

## 6. 电商前贴案例示例

假设任务是“为护肤品正片制作 6 秒电商前贴”。

### Strategy 提供

- 目标：提高前三秒停留和商品点击。
- 受众：关注初老问题、对功效宣传敏感的女性。
- 核心主张：突出产品使用后的水润感。
- 证据：只能使用已批准的成分和功效表述。
- 推荐路线：结果先行或商品揭幕。
- 实验假设：商品揭幕比纯口播更能提高前三秒停留。
- 主要变量：首个动作。
- 限制：商品包装和文字不能变形，不能使用未经批准的功效承诺。

### Creative 决定

- 使用哪种商品揭幕方式。
- 0–1.5 秒的具体构图。
- 手部动作、光线、镜头和声音。
- 生成图片与视频使用的 Prompt。
- 如何与后续正片拼接。
- 生成多少候选以及如何重试。
- 如何进行画面、品牌、事实和技术质检。

### 结果回流

至少需要关联：

```text
Strategy 版本
→ 实验假设
→ Creative 能力及版本
→ CreativeTask
→ CreativeVersion
→ AssetVersion
→ 投放实验单元
→ 指标观察窗口
→ 人工确认结论
```

## 7. 对齐会议议程

建议召开一次 60 分钟会议。

| 时间 | 议题 | 目标 |
| --- | --- | --- |
| 0–10 分钟 | Strategy 说明对齐背景 | 确认为什么要对齐，以及本次不讨论什么 |
| 10–25 分钟 | Creative 介绍真实能力 | 区分正式、Beta、实验、规划能力 |
| 25–40 分钟 | 真实案例走查 | 找出信息缺口、阻断条件和职责争议 |
| 40–50 分钟 | 确认双方边界 | 冻结 Strategy 输入和 Creative 输出 |
| 50–60 分钟 | 确认首期计划 | 确定范围、负责人、时间和验收标准 |

会议中先不要深入讨论：

- 数据库表设计。
- 具体 JSON 字段名称。
- Provider 厂商和模型选择。
- Prompt 模板细节。
- 所有未来能力的一次性大方案。

这些内容应在业务边界和首期案例确认后，由双方研发继续设计。

## 8. 会议必须形成的结论

会议结束前确认以下内容：

- [ ] 当前 Creative 能力清单及真实成熟度。
- [ ] Strategy 和 Creative 的职责边界。
- [ ] 首期选定的真实创作任务。
- [ ] Strategy 需要提供的最小输入。
- [ ] Creative 返回的最小结果。
- [ ] planning、generation、production 三阶段阻断条件。
- [ ] Strategy 版本是否需要更新的判断规则。
- [ ] 创意结果回流需要保留的关联 ID。
- [ ] 双方产品和研发负责人。
- [ ] 首期时间计划和验收标准。

## 9. 首期交付建议

首期先完成四项交付：

1. 一张真实的 Creative 能力清单。
2. 一个 Strategy 根据项目条件匹配能力的入口。
3. 一份 Strategy → Creative 的任务交接样例。
4. 一条从 Strategy 假设到 Creative 产物和效果指标的追溯链路。

首期不要求：

- 一次接入全部 Creative 能力。
- 自动修改已批准 Strategy。
- 自动把单次投放结果升级成策略经验。
- Strategy 直接控制 Creative 模板和 Prompt。
- 为能力目录重新建设一套 Provider 系统。

## 10. 可直接发送给 Creative 团队的消息

> Creative 最近开放了较多新能力，我们希望 Strategy 能够根据项目目标推荐合适的创作路线，并给 Creative 提供可直接开工的目标、受众、主张、证据、约束和实验假设。
>
> 这次对齐不是让 Strategy 介入脚本、分镜、Prompt 或具体生成，而是希望共同确认：目前有哪些真实可用的 Creative 能力、每项能力需要什么上游输入、缺什么时应如何阻断，以及创意结果如何回到 Strategy 复盘。
>
> 建议先选择一个真实任务，例如电商前贴，跑通 Strategy → Creative → 效果回流，再将模式复制到其他能力。会议希望最终确认能力清单、职责边界、首期案例、交接样例、负责人和验收标准。

## 11. 最终原则

> 先对齐如何合作，再对齐系统怎么实现；先跑通一个具体任务，再扩展所有能力。
