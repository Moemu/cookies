# cookies PRD 通用交互与质量要求

| 属性 | 内容 |
| --- | --- |
| 适用范围 | 四个垂直系统和共享管理台 |
| 文档版本 | v0.2 |
| 文档状态 | 草案 |

## 1. 目的

本文件定义不应在四份 PRD 中重复的通用产品要求。各系统 PRD 负责业务差异；本文件负责状态、错误、协作、可追踪性、AI 披露和发布质量。

## 2. 页面状态

每个列表、详情、编辑器、对话和长任务页面必须设计：

- 首次空状态、筛选无结果、无权限和资源不存在。
- 首屏加载、局部刷新、后台同步和数据过期。
- 排队、运行、等待用户/审批、部分完成、失败、取消和结果未知。
- 可重试与不可重试错误，以及不会丢失已有输入的恢复方式。
- 上游系统不可用时的只读、缓存或延迟状态。

错误信息包含发生了什么、保留了什么、用户可以做什么和诊断 ID，不展示厂商/数据库内部错误。

## 3. 状态转换矩阵

每个业务实体必须在详细设计前补充：当前状态、动作、前置条件、权限、目标状态、失败状态、是否可撤销、通知和审计事件。

通用原则：

- 已确认/批准版本不可编辑；修改创建新草稿。
- 审批绑定具体版本和内容哈希，关键变化使审批失效。
- 外部写入结果未知是独立状态，不等于失败。
- 停用/归档不物理删除历史引用。
- 状态转换只能由拥有该实体的业务服务执行。

## 4. 自动保存与并发编辑

- 编辑器自动保存显示最后成功时间、未保存状态和失败恢复。
- 使用资源版本/ETag 防止覆盖；冲突提供逐字段或逐章节比较。
- 多人评论与评审不锁死草稿编辑，但提交评审创建不可变版本。
- 离线或页面关闭前保留本地恢复草稿，不把本地状态直接视为服务端事实。

## 5. 搜索、筛选与批量操作

- 系统内搜索仅搜索当前系统和授权范围；全局搜索返回资源类型、系统和版本入口。
- 列表保留筛选、排序、列配置和分页位置，分享链接不泄露未授权条件。
- 批量操作先展示对象数、不可处理项、预计成本/影响和是否可撤销。
- 部分成功返回成功、失败和未知对象清单，可只重试失败项。

## 6. 通知与待办

- 通知与业务状态分离，发送失败不回滚业务事实。
- 用户可配置非安全类通知偏好；审批、预算风险和安全事件不能被普通用户完全关闭。
- 待办包含对象、原因、截止时间、发起人和明确动作，完成后保留历史。
- 相同对象和原因合并降噪，重要状态变化重新提醒。

## 7. AI 输出与披露

- AI 生成/提取/建议内容明确标识，不伪装成人工确认事实。
- 展示来源、版本、适用范围、置信提示、模型/Skill 血缘和最后更新时间。
- 用户可反馈采纳、修改、拒绝、举报及原因。
- 涉及真人、声音、商标、版权和敏感行业时展示额外风险与审批。
- 导出/交付包携带所需 AI 标识、水印、权利清单和平台披露字段。

## 8. 需求可追踪性

每个需求 ID 在进入开发时关联：

| 项目 | 要求 |
| --- | --- |
| 用户场景 | 角色、目标和前置条件 |
| 交互 | 页面/流程稿与所有状态 |
| 数据 | 实体、字段、版本、Owner 和留存 |
| 接口 | OpenAPI/事件 Schema 和错误码 |
| 权限 | 读取、编辑、确认、批准和高风险动作 |
| 埋点 | 成功、失败、中断、成本和质量事件 |
| 测试 | 正常、边界、故障、安全和可访问性用例 |
| 发布 | Feature Flag、灰度范围、Owner 和回滚 |

需求完成必须同时满足功能验收、数据/接口契约、可观测性和安全验收。

## 9. 页面布局与图表质量

### 9.1 页面布局

- 除信息展示页外，每个页面必须围绕一个主任务组织，默认只设置一个主工作区和一个辅助区。
- 普通页面同一横排不超过两个主要模块；禁止连续使用三至四个同尺寸模块横向平铺。
- 对话、表单、创作、评审页面不得为了填满桌面宽度压缩留白或同时展示所有次级信息。
- 三栏页面必须有明确主次比例，主区域至少占内容宽度的 50%，第三栏应可收起或明显弱化。
- 次级属性、证据、版本、历史、日志和高级配置通过标签、检查器、抽屉或下钻渐进披露。
- 信息展示页、监控页和作战台允许较高密度，但必须明确主指标、异常、主要操作和从上到下或从左到右的扫描顺序。
- 页面设计稿必须标注主任务、主要操作和前三个视觉落点，无法说明阅读动线的页面不能进入开发。

### 9.2 图表质量

- 图表必须先保证指标定义、单位、坐标、图例或直接标签、时间范围、数据新鲜度和置信信息清晰。
- 每个分析页面选择一个主要图表作为视觉锚点，避免多个同权重小图组成数据墙。
- 在准确表达基础上，通过关键节点标注、基线对比、素材缩略图关联、时间轴同步、留白和线条节奏进行创意化表达。
- 创意表达不得扭曲比例、截断基线、隐藏样本、夸大差异或用装饰替代数据。
- 图表需要提供文字摘要、数据表或其他可访问替代，并支持键盘和减少动效偏好。

## 10. 可访问性、国际化与设备范围

- 官网、四大业务系统和运营后台只支持桌面 Web，不设计或验收手机、平板页面。
- 设计基准视口宽度为 1440px，最低支持宽度为 1280px；低于 1280px 可展示桌面使用提示，不要求响应式重排。
- 创意预览仍需提供目标手机广告画幅和排版预览，这属于广告内容模拟，不属于移动端页面支持。
- 关键操作支持键盘、可见焦点、语义化标签和不依赖颜色的状态表达。
- 文案可本地化；时间、币种、数字和时区显式展示。
- 用户内容支持多语言，界面 MVP 默认简体中文。

## 11. 运营与客服能力

平台运营后台需支持：租户/任务诊断、异步任务补偿、死信/映射修复、Provider/Connector/Skill 停用、风险事件和审计查询。

- 客服访问客户内容必须获得临时授权并写审计。
- 人工修复不能直接改写不可变版本或绕过业务状态机。
- 补偿任务保存原因、操作者、输入快照、影响对象和结果。

## 12. MVP 验收

1. 四系统核心页面均覆盖空、加载、失败、部分成功、无权限和恢复状态。
2. 业务实体有状态转换矩阵并由 Owner 服务强制执行。
3. 81 个现有需求 ID 可关联设计、接口、埋点和测试用例。
4. AI 生成内容、提取特征和建议在界面与交付物中可识别。
5. 高风险批量动作显示影响范围并处理部分成功。
6. 运营人员能在不越权修改业务事实的前提下诊断和补偿任务。
7. 除信息展示页外，核心页面不存在三个以上同权重模块横向平铺，并能说明主任务和阅读动线。
8. 核心分析页面的主图表同时通过数据可读性、创意表达和可访问性评审。
