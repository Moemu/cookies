# 抖音 AI 效果广告创作规则 v1

- 状态：P0 内部草案
- 适用能力：创意创作 / 视频创作 / 效果广告 / AI 效果广告生成
- 适用渠道：抖音
- 注意：本文是 Cookies 的创作与生成默认值，不是抖音官方投放规范，也不构成“爆款”或投放效果承诺

## 1. 目标

根据用户确认的商品信息和补充需求，生成结构完整、节奏清晰、适合抖音竖屏观看的效果广告素材。首版优先保障：开场意图明确、商品出现及时、卖点可视化、字幕静音可理解、结尾转化动作清楚。

## 2. 默认媒体规格

| 项目 | P0 默认值 |
|---|---|
| 画幅 | 9:16 |
| 成片时长 | 15～30 秒，由用户选择 |
| 工作分辨率 | 720×1280；Provider 能力验证后再开放 1080×1920 |
| 成片帧率 | 25 fps |
| 视频编码 | H.264 / yuv420p |
| 音频编码 | AAC，48 kHz，双声道 |
| 默认语言 | 简体中文 |
| 字幕 | 后期生成，不要求视频模型绘制文字 |
| 视频模型音频 | 默认静音；旁白、BGM、音效统一后期合成 |

其他渠道可以显示“规划中”，但不能使用本规则生成并宣称已经完成渠道适配。

## 3. 脚本结构

脚本只能使用用户在需求分析阶段确认的商品名称、受众、描述和核心卖点。每次只生成一个完整脚本。

建议结构：

1. **痛点或场景开场**：0～3 秒，直接建立目标受众能够识别的问题、需求或结果期待。
2. **商品快速出现**：原则上前 5 秒内明确展示商品，避免长时间只有抽象氛围。
3. **核心卖点展示**：围绕 1～3 个已确认卖点组织，每个卖点必须有可执行的视觉表现。
4. **使用场景或结果承接**：展示商品如何进入真实场景，避免只朗读参数。
5. **转化结尾**：明确商品、行动和必要条件；不得把未确认优惠写入 CTA。

脚本总时长必须等于用户选择的成片时长，各段时间不可重叠或留出无解释空档。

## 4. 开场规则

开场只选择一个主要机制，避免在前三秒同时堆叠多个表达：

- 痛点直入；
- 结果先行；
- 场景触发；
- 对比反差；
- 商品动作；
- 问题提问；
- 明确利益点。

开场必须满足：

- 无声音时仍能理解主要问题或利益；
- 不依赖无法证明的夸张结果；
- 不使用与商品无关的刺激画面骗取停留；
- 与后续卖点、商品和 CTA 保持同一表达承诺。

## 5. 卖点与画面规则

- 一条成片默认选择 1 个主卖点和最多 2 个辅助卖点。
- 卖点尽量通过动作、对比、场景或细节镜头表现，不只依赖旁白和字幕。
- 商品首次出现后，包装、颜色、Logo、结构和关键部件保持连续。
- 商品真实外观优先使用链接提取或用户上传的图片作为参考。
- 商品名称、价格、优惠、Logo 和 CTA 文字在后期叠加，不要求视频模型直接生成可读文字。
- 人物、商品和场景参考素材必须标明角色，不能把场景参考误当商品身份参考。

## 6. Storyboard Shot 规则

每个 Shot 必须包含：

- 开始时间、结束时间和时长；
- 画面内容；
- 人物、商品和动作；
- 景别与运镜；
- 参考图片；
- 旁白；
- 字幕；
- 音效；
- BGM cue；
- 生产方式。

叙事 Shot 建议 2～5 秒。模型 GenerationUnit 必须服从实际 Provider 的时长限制；当 Shot 小于视频模型最小时长时，可以生成较长素材后裁切，或将相邻 Shot 聚合进一个 GenerationUnit。Storyboard Shot 与模型 GenerationUnit 不要求一一对应。

## 7. 旁白规则

- 默认使用一名旁白，整条广告保持同一音色、语速和情绪方向。
- 旁白用自然口语表达，避免连续罗列规格。
- 旁白内容必须能在对应镜头时间内正常说完，不能依赖异常加速。
- 商品名称、专有词和数字需要提供发音字典或人工确认。
- 视频模型生成的声音不能替代已经确认的精确旁白；P0 使用独立 TTS 后期合成。

## 8. 字幕规则

- 字幕由确认后的脚本和 TTS 时间戳产生。
- 单屏优先 1～2 行，避免遮挡商品主体、人物面部和 CTA。
- 核心词可以使用有限强调样式，但不让每个词都跳动。
- 字幕必须与旁白语义一致；允许为了阅读压缩口语，不允许增加新卖点。
- 字幕样式、字体、字号、描边、安全区作为 ChannelProfile 配置，不写死在各业务页面。

## 9. 音乐与音效规则

- P0 默认从已授权 BGM/音效库选择，不把未知来源音乐交给成片。
- BGM 服务画面节奏，不遮盖旁白；旁白出现时自动降低 BGM 音量。
- 音效只强化真实动作、转场和商品反馈，避免无意义密集堆叠。
- 每条音频保存素材 ID、版本和使用范围；AI 生成音乐也必须记录生成来源和许可条件。

## 10. CTA 规则

- CTA 与用户选择的转化目标一致。
- 没有已确认价格或优惠时，使用“点击了解更多”等中性表达。
- 有条件的优惠必须保留条件和有效期，不允许模型自行补写“最低价”“限量”或倒计时。
- CTA 放在结尾并保持可读停留，不只依赖一帧闪现。

## 11. Prompt 编译顺序

模型请求由服务端确定性组合：

```text
系统输出约束
+ 抖音 AI 效果广告创作规则版本
+ 已确认 RequirementRevision
+ 当前脚本/故事板任务目标
+ 用户重新生成反馈（如有）
+ 品牌与项目限制
+ JSON Schema
```

成片需要记录本规则的版本和内容 Hash。修改规则时新增版本并经过固定商品 Fixture 回归，不静默改变正在进行的任务。

## 12. P0 评测样例

至少准备以下固定样例：

- 背包：结构、扩容、面料和多场景；
- 美妆：包装文字、产品质感和功效表达边界；
- 3C：产品结构、界面真实性和功能演示；
- 无价格/优惠商品；
- 图片不足、链接解析失败的人工上传降级。

评测维度：脚本结构完整、商品出现时间、卖点与画面对应、总时长、旁白可说完、字幕密度、商品连续性、CTA 是否使用已确认事实。
