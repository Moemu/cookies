# cookies 广告数据 Connector 与指标规范

| 属性 | 内容 |
| --- | --- |
| 定位 | 广告平台、内容平台和业务转化数据的统一接入与标准化层 |
| 首期范围 | 抖音/快手优先；小红书、公众号按可用授权和数据方式接入 |
| 文档版本 | v0.1 |
| 文档状态 | 草案 |

## 1. 目标与边界

Connector 层负责取得、保存和标准化数据，不负责生成素材结论；素材洞察系统负责分析，智能投放系统负责执行与监控。

- 优先使用平台正式 API；无 API 时使用授权报表导入；Computer Use 读取只作为受控补充。
- 原始平台事实不可被统一指标覆盖，任何标准化结果都能回溯原字段和批次。
- Connector 凭据由密钥服务管理，不进入浏览器前端、Agent 上下文或业务日志。

## 2. 数据源类型

| 类型 | 优先级 | 用途 |
| --- | --- | --- |
| 官方 API/OAuth | 首选 | 账户、Campaign、广告、创意、指标和审核状态 |
| 服务账号/API Key | 受平台支持时 | 企业服务集成，按最小权限和组织隔离 |
| 文件导入 | API 不可用或历史回补 | CSV/XLSX/平台报表，保留原文件和模板版本 |
| Computer Use 读取 | 补充 | 页面状态或少量只读字段，必须保存新鲜度和证据 |
| 业务转化源 | 按项目 | CRM、订单、线索、应用事件和品牌调研指标 |

## 3. Connector 实体

- `DataSource`：组织、平台、数据类型、地区、状态和负责人。
- `Connection`：授权方式、凭据引用、账户范围、权限和过期时间。
- `SyncCursor`：对象、时间窗口、分页标记和水位线。
- `ImportBatch`：来源、文件/请求、Schema 版本、时间范围、状态和错误。
- `RawRecord`：平台原始记录、来源主键、发生/同步时间和内容哈希。
- `CanonicalEntityMapping`：平台对象与 cookies Project/CreativeVersion/DeliveryPlan 的映射。
- `MetricDefinition`：原始/统一指标、公式、单位、粒度、版本和适用平台。
- `MetricSnapshot`：冻结的数据窗口、口径、数据时间、新鲜度和质量状态。

## 4. 数据分层

1. **Raw**：保持平台字段、原始精度和响应/文件批次，仅追加和更正标记。
2. **Normalized**：统一时间、币种、金额精度、对象层级、枚举和缺失值。
3. **Canonical**：映射 cookies 项目、创意版本、投放对象和统一指标。
4. **Snapshot**：供分析、报告和 Agent 使用的不可变数据窗口。

模型和 Agent 只读取经过权限裁剪的 Canonical/Snapshot，不直接消费访问令牌或无界 Raw 数据。

## 5. 对象映射

映射链：`Organization → PlatformAccount → Campaign/AdGroup/Ad → PlatformCreative → CreativeVersion → Asset`。

- 优先在投放创建时保存平台对象 ID 与 cookies 来源版本。
- 外部既有广告通过名称、素材哈希、落地页、创建时间等生成候选，不自动确认歧义匹配。
- 一对多、多对一和素材复用关系显式保存有效时间。
- 未匹配记录进入人工队列，不参与需要创意级归因的强结论。
- 映射修改创建新版本并触发受影响 Snapshot 重算，不静默改写历史报告。

## 6. 指标与归因

每个指标定义至少包含：平台、原字段、公式、单位、粒度、发生时间、归因窗口、去重方式、数据延迟和可比较范围。

- 金额使用定点数和币种；跨币种需保存汇率来源、日期和原金额。
- 时间同时保存平台时区与 UTC，日粒度按平台账户时区聚合。
- CTR、CVR、CPA、ROAS 等派生指标由版本化公式计算，分母为零返回不可用而非零。
- 跨平台比较默认关闭；显式开启时展示差异和标准化限制。
- 转化同时保存平台归因和业务事实口径，不强行合并。
- 数据窗口未成熟、追踪异常或延迟超阈值时，阻止确定性优化建议。

## 7. 同步、回补与对账

- 首次同步按账户/时间切片回补；增量同步使用更新时间、水位线和重叠窗口。
- API 限流使用连接级令牌桶、退避和可恢复游标。
- Upsert 以平台主键、数据日期、归因窗口和 Schema 版本组合保证幂等。
- 最近窗口定期重拉以吸收延迟归因，历史窗口按更正策略冻结。
- 每批记录请求范围、返回数量、丢弃/错误数量、校验和与水位线。
- 对账覆盖平台总消耗、对象数量、日期连续性、币种、映射率和关键指标。

## 8. 文件导入

- 上传后先执行病毒扫描、文件类型/大小和编码检查。
- 用户选择平台模板、账户、时区、币种、数据范围和字段映射。
- 预览解析结果、重复行、非法值、未知字段和覆盖影响后再确认导入。
- 原文件、模板版本、字段映射和错误报告可追溯。
- 相同文件哈希和导入范围默认阻止重复；确需重导创建更正批次。

## 9. 安全与权限

- Connection 按组织、平台账户和只读/写作用域隔离；数据 Connector 默认只读。
- OAuth 刷新令牌/API Key 加密保存、自动轮换或过期告警。
- 用户只能同步其可访问的账户，服务身份需明确项目范围。
- 客户名单、线索、订单和设备标识按高敏数据处理并最小化进入分析层。
- 导出、删除、跨地域和长期留存遵循组织策略并写审计。

## 10. API 与事件

- `/platform/v1/connectors/sources/*`、`connections/*`、`sync-runs/*`。
- `POST /api/insights/v1/metric-imports`、`GET /api/insights/v1/data-quality`。
- `connector.sync.completed.v1`、`connector.sync.failed.v1`。
- `delivery.metrics.updated.v1`、`asset.mapping.changed.v1`。

数据更新事件携带数据源、对象范围、窗口、Snapshot 版本和质量状态，不携带整批指标。

## 11. 质量状态

`healthy`、`delayed`、`partial`、`mapping_incomplete`、`tracking_broken`、`reconciling`、`blocked`。

任何洞察和优化建议必须展示所用 Snapshot 的质量状态和数据截止时间。

## 12. MVP 验收

1. 至少一个首发平台可完成授权、历史回补、增量同步和撤销。
2. 同一批次重跑不产生重复 Raw 或指标记录。
3. 投放创建的对象能关联到批准的 CreativeVersion。
4. 未匹配、延迟或异常数据不会产生强洞察或自动优化动作。
5. 指标能回溯平台原字段、批次、公式版本、时区、币种和归因窗口。
6. 平台总消耗和对象数量可对账，差异进入修复队列。
7. 凭据不会进入前端、Agent、导出文件或普通日志。
