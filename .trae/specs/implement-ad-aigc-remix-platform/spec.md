# 广告 AIGC 与 AI 混剪平台 Spec

## Why
当前项目已经具备新版素材库、RemixPlan 和 RenderJob 草案能力，但视频素材缺少真实媒体元数据、多模态特征、持久化渲染状态、质量治理和产物回流。该变更把飞书资料沉淀出的 11 个技术点按平台能力落地，使 AI 混剪从规则草案升级为可恢复、可追溯、可评测、可持续优化的广告 AIGC 生产闭环。

## What Changes
- 为视频资产补充真实 `duration/fps/codec/poster` 元数据，并增加 `AssetFeature` 多模态标签承载。
- 将 `RemixPlan` 从 clip 草案升级为兼容 `Shot` 的标准时间线协议。
- 将 `RenderJob` 从进程内内存任务升级为持久化状态机，支持幂等、恢复、进度和重试。
- 将渲染成片回流到素材库，记录 `Provenance` 和输入素材血缘。
- 增加 `QualityReport`，覆盖 VLM 质检、主体缺陷、画面崩坏、美感和合规风险。
- 增加 `HitAnalysis` 与 `ProductMapping`，支持爆款视频结构拆解和产品映射复刻。
- 增加 AI 前贴 Hook 生成，为 opening 段生成 3-10 秒强钩子前贴。
- 增加 Agent 运行、工具调用和 Trace 结构，支撑编导、素材优选、质检和渲染诊断 Agent。
- 增加 Knowledge/RAG 策略库入口，使飞书资料、项目 docs、素材复盘可追溯引用。
- 增加 Remix-MMLU 评测集与评测运行，覆盖 Planner、Prompt、Agent 和质检回归。
- 增加反馈飞轮，沉淀人工评分、渲染结果和投放表现，供素材优选和 Planner 权重使用。

## Impact
- Affected specs: 媒体资产平台、统一模型 Provider、Codex 与 Skills 运行时、API 与领域事件契约、AI Bulk Remix Design、广告 AIGC 与 AI 混剪开发知识沉淀。
- Affected code: `internal/platform/assets`、`internal/platform/remix`、`internal/platform/provider`、`internal/platform/httpserver`、`internal/platform/jobruntime`、`internal/platform/knowledge`、`web/src/features/assets`、`api/openapi/platform-v1.yaml`、`migrations/*`。

## ADDED Requirements

### Requirement: 视频资产元数据
The system SHALL persist real video metadata for asset versions, including duration, fps, codec, bitrate, audio metadata, poster frame reference, probe status and probe error.

#### Scenario: 上传视频后可读取真实时长
- **WHEN** a video asset upload completes and media probing succeeds
- **THEN** the asset version includes `duration_seconds`, `fps`, `codec` and a poster frame reference

#### Scenario: 探测失败可诊断
- **WHEN** media probing fails
- **THEN** the asset version keeps the original file but marks `probe_status=failed` and records a readable `probe_error`

### Requirement: AssetFeature 多模态标签
The system SHALL store versioned `AssetFeature` payloads for video/image assets, including hook strength, product visibility, scene tags, product tags, person/action/emotion tags, selling points, CTA presence, similarity group and evidence.

#### Scenario: Planner 使用素材特征
- **WHEN** a remix planner reads project video assets with features
- **THEN** it can use `hook_strength`, `product_visibility`, `selling_points` and `similarity_group` as scoring inputs

### Requirement: Shot List 协议
The system SHALL represent remix timeline entries as `Shot` records while preserving backward compatibility with existing clip-based plans.

#### Scenario: 保存 v2 RemixPlan
- **WHEN** a user saves a remix plan generated by the new planner
- **THEN** the backend stores `schema_version=remix_plan_v2` and returns segment `shots`

#### Scenario: 读取历史 clip 草案
- **WHEN** a user opens an existing clip-based remix plan
- **THEN** the system still renders it and can derive compatible shots without data loss

### Requirement: RenderJob 持久化状态机
The system SHALL persist remix render jobs with status, progress, input snapshot, idempotency key, request hash, output asset, error code, error message and timestamps.

#### Scenario: 重启后恢复渲染任务
- **WHEN** the API service restarts after a render job is created
- **THEN** the job can still be queried with its last persisted status and progress

#### Scenario: 幂等创建
- **WHEN** the same `Idempotency-Key` and same request body are submitted twice
- **THEN** the system returns the same render job instead of creating a duplicate

#### Scenario: 幂等冲突
- **WHEN** the same `Idempotency-Key` is submitted with a different request body
- **THEN** the system returns a conflict error and does not create a new job

### Requirement: 渲染产物回流素材库
The system SHALL ingest successful render outputs into Assets as stable asset versions and record provenance relations from output to RemixPlan, RenderJob and input assets.

#### Scenario: 成片可在素材库查看
- **WHEN** a render job succeeds
- **THEN** its output is visible as a project asset and can be previewed through the existing asset preview API

### Requirement: QualityReport 质检
The system SHALL create quality reports for generated or remix output assets, including verdict, score, subject defects, corruption, aesthetics, compliance issues, evidence and repair suggestions.

#### Scenario: 严重缺陷阻断导出
- **WHEN** a quality report contains a critical issue
- **THEN** the render flow enters `requires_review` or fails according to policy and does not silently mark the output as ready

### Requirement: HitAnalysis 爆款分析
The system SHALL analyze a source video into structured hit-analysis data containing video meta, narrative structure, segments, scripts, visual elements, conversion nodes and replication insights.

#### Scenario: 生成爆款结构
- **WHEN** a user requests hit analysis for a ready video asset
- **THEN** the system returns continuous, non-overlapping segments with timestamps and narrative roles

### Requirement: ProductMapping 产品映射
The system SHALL map a hit-analysis structure to a target product and project assets, producing replacement rules and constraints for remix plan generation.

#### Scenario: 生成复刻草案
- **WHEN** a user creates a product mapping and requests a remix plan
- **THEN** the system creates a Shot-based RemixPlan that reuses structure but references authorized project assets

### Requirement: AI 前贴 Hook
The system SHALL generate or draft 3-10 second opening preroll hooks for remix plans, using hook type, reference asset, style constraints and quality gates.

#### Scenario: 前贴插入 opening 段
- **WHEN** a generated preroll passes quality checks and user applies it
- **THEN** the preroll is inserted as an opening shot and timeline seconds are recalculated

### Requirement: Agent Run 与 Trace
The system SHALL persist Agent runs, tool calls and trace spans for director, asset selection, quality and render diagnosis workflows.

#### Scenario: 可追溯 Agent 执行
- **WHEN** an Agent produces a Shot List or diagnosis
- **THEN** the user can inspect steps, tools, model spans, citations and output references

### Requirement: Knowledge/RAG 策略库
The system SHALL import and search project knowledge documents with citations, including docs, strategy notes, Feishu-derived summaries and asset retrospectives.

#### Scenario: 输出引用知识来源
- **WHEN** Planner or Agent uses knowledge search
- **THEN** the output includes citations linking to the source document/chunk

### Requirement: Remix-MMLU 评测
The system SHALL store evaluation cases and run repeatable evaluation jobs for planner, prompt, agent and quality check regressions.

#### Scenario: 固定评测可重复
- **WHEN** an eval run is executed twice against the same inputs and version
- **THEN** scores and failed cases are reproducible

### Requirement: 反馈飞轮
The system SHALL append feedback events for remix plans, render jobs and assets, then expose aggregated performance snapshots for future planner weighting.

#### Scenario: 用户评分被记录
- **WHEN** a user rates a remix plan or output asset
- **THEN** the feedback event is appended and can be queried without mutating historical plan data

## MODIFIED Requirements

### Requirement: AI 混剪 Planner
The system SHALL continue supporting deterministic remix planning, but scoring SHALL prefer real media metadata and AssetFeature signals when present, falling back to existing heuristics only when advanced metadata is unavailable.

### Requirement: Provider 输出边界
Generated media outputs SHALL continue to flow through generated intake or equivalent asset ingestion. Business modules SHALL NOT store vendor URLs, temporary file paths or object storage keys as public contract fields.

### Requirement: 前端视觉与可用性
AI remix pages SHALL maintain polished desktop UX at 1280px, 1440px and 1680px widths, with clear hierarchy, visible progress, accessible controls, explicit AI lineage and no horizontal overflow.

## REMOVED Requirements

### Requirement: RenderJob 仅内存存储
**Reason**: In-memory jobs cannot survive restarts, cannot support retries, and cannot provide reliable CI or production behavior.
**Migration**: Keep memory service only for unit tests; production and local API composition SHALL use persistent store-backed render jobs.
